# Storage v2 bucket operations

<!-- markdownlint-configure-file {"MD013": false} -->

Scope: RPC-STORAGE-001–004, the bucket portion of BEHAVIOR-RPC-001 and AUDIT-008. All broader rows remain PARTIAL until their remaining contracts are verified. The [2026-11-18 bucket changes](#bucket-changes-on-2026-11-18) also cover UpdateBucket, LockBucketRetentionPolicy and SetIamPolicy (RPC-STORAGE-005, 007 and 009) and the bucket cases of BEHAVIOR-RPC-002, whose contract is the [update/copy slice](grpc-v2-update-copy.md).

## Acceptance contract

- Parse `projects/_/buckets/NAME`, reject malformed names with INVALID_ARGUMENT, and require and decode `x-goog-request-params` routing metadata without allowing it to override the request.
- Get existing buckets, return NOT_FOUND for missing buckets, compare both metageneration conditions as they arrive, and project supported read masks. A read mask path that names no Bucket field returns INVALID_ARGUMENT with Cloud Storage's wording (`There is no field for this resource named '<path>'.`, recorded 2026-11-18); `satisfies_pzs` and nested paths return UNIMPLEMENTED with ErrorInfo. The settings bucket creation and update refuse (`billing`, `custom_placement_config`, `encryption`, `hierarchical_namespace`, `ip_filter`, `logging`, `rpo`, `website`) are never stored, so a read mask may select them and gets them unset, as Cloud Storage answered for a bucket without them (case `grpc-bucket-unset-settings-mask`, recorded 2026-11-15). The Java SDK names every one of them in its default bucket read mask. `satisfies_pzs` and nested paths stay UNIMPLEMENTED.
- Create using empty or `projects/_` parent and `bucket.project = projects/<id>` (including `_`), with the JSON-supported metadata subset. Duplicate names return ALREADY_EXISTS. Unsupported semantics return UNIMPLEMENTED rather than being ignored.
- List by project and prefix with bounded page size and project/prefix-bound continuation tokens.
- Delete empty buckets with atomic metageneration conditions; nonempty buckets return FAILED_PRECONDITION `The bucket you tried to delete is not empty.` and retain their contents, and a not-match condition that alone fails answers FAILED_PRECONDITION `The resource you requested has not been modified according to the condition you specified.` (both recorded 2026-11-18). A live or noncurrent object keeps the bucket; soft-deleted objects and unfinished XML multipart uploads do not, as the proto says (storage.proto lines 76-95), and neither does an unfinalized appendable object, a local choice described below. A bucket with a soft delete policy is kept as a soft-deleted version.
- Reuse shared authorization: strict requests denied without credentials return UNAUTHENTICATED and registered callers without permission receive PERMISSION_DENIED. Anonymous Get/Delete honors effective allUsers grants and public access prevention, exactly like JSON.
- Ordinary Go `storage.NewGRPCClient(ctx)` supports Bucket.Create, Bucket.Attrs, Buckets iteration and Bucket.Delete with omitted optional arguments.
- JSON-created buckets are visible through gRPC and gRPC-created buckets are visible through JSON.

## Boundaries and sources

No setting, dependency, storage implementation or startup change is needed. CreateBucket reuses shared typed retention, soft-delete, PAP, CORS and Autoclass validators. Creation still builds a JSON insert resource for the remaining creation fields; a shared creation builder is not yet implemented, and this operation stays PARTIAL. UpdateBucket constructs shared typed updates directly. Both use shared bucket authorization and the transactional catalog. Bucket deletion and listing retain catalog concurrency and memory bounds.

Deletion implements the shared native empty-bucket contract through the same catalog transaction as JSON, including the soft-deleted version a bucket with a soft delete policy leaves ([bucket soft delete](bucket-soft-delete-restore.md)); the pinned Storage v2 proto has no RPC that lists or restores soft-deleted buckets. An unfinished XML multipart upload does not keep a bucket. Neither does an unfinalized appendable object, a recorded local choice: the proto does not say whether one is a live object, and its open writer finds it superseded at the next flush.

Create supports location, storage class, labels, CORS, versioning, default event hold, retention/soft-delete durations and IAM uniform access/public access prevention through the same native JSON validation. Empty or disabled unsupported configurations that equal their protobuf defaults, and `rpo=DEFAULT`, are accepted; an empty `website` message is the exception and is refused. A retention duration's nanos are rounded down to whole seconds, as the proto says (storage.proto lines 2429-2433) and as UpdateBucket does, so a duration under one second is no period and answers INVALID_ARGUMENT. Fields the proto marks OUTPUT_ONLY (`bucket_id`, `metageneration`, `location_type`, `create_time`, `update_time`, `owner` and the Autoclass `toggle_time` and `terminal_storage_class_update_time`) are ignored, as `google.api.field_behavior` requires, and the new bucket carries the server's values. Autoclass uses the shared configuration rules in [bucket-autoclass-storage-class](bucket-autoclass-storage-class.md). Object retention is enabled by `enable_object_retention` ([SDK parity](grpc-v2-sdk-parity.md)). Billing, encryption, logging, website, custom placement, hierarchical namespace, IP filtering, `satisfies_pzs=true` and an `rpo` other than `DEFAULT` return UNIMPLEMENTED on purpose: the JSON API stores none of them either (SPEC-GRPC-UNMODELED-SETTINGS). A nonempty lifecycle, bucket or default object ACL and the predefined ACLs also return UNIMPLEMENTED today; those are pending work, listed under [ledger cases](#ledger-cases). A fractional soft delete duration answers INVALID_ARGUMENT `Invalid argument.` with a `BadRequest`, the answer Cloud Storage gave UpdateBucket (recorded 2026-11-18); CreateBucket shares the helper, and its own answer was not recorded because the harness cannot create a bucket. A nonempty `etag`, a retention or soft delete `effective_time`, a locked retention policy and a uniform access `lock_time` are refused with UNIMPLEMENTED as recorded local choices, because the proto does not mark them output only (SPEC-GRPC-LOCAL-CHOICES).

Read masks support the top-level fields `name`, `bucket_id`, `etag`, `project`, `metageneration`, `location`, `location_type`, `storage_class`, `autoclass`, `labels`, `create_time`, `update_time`, `default_event_based_hold`, `versioning`, `cors`, `lifecycle`, `retention_policy`, `soft_delete_policy`, `object_retention` and `iam_config` ([SDK parity](grpc-v2-sdk-parity.md)), and the never-stored settings, which come back unset. Absent/empty masks and a single `*` return this converted subset. `*` beside a name returns INVALID_ARGUMENT with Cloud Storage's recorded message. A top-level name that is no Bucket field returns INVALID_ARGUMENT `There is no field for this resource named '<path>'.`, as Cloud Storage answered GetBucket and ListBuckets (recorded 2026-11-18). Nested paths such as `versioning.enabled` return UNIMPLEMENTED with ErrorInfo, although Cloud Storage serves a nested member of a message and names no field for a member the message lacks, a `labels` key or a sub-field of the repeated `acl`; that refusal is a declared local choice (SPEC-GRPC-LOCAL-CHOICES), so a nested path under a Bucket field never answers INVALID_ARGUMENT here. `satisfies_pzs` returns UNIMPLEMENTED on purpose. GetBucket checks the mask right after the bucket name, before authorization and lookup; ListBuckets checks it after the caller, the project permission, `page_size` and `prefix` and before the page token (SPEC-GRPC-LOCAL-CHOICES: the order was recorded only for a negative `page_size`, which wins over an unknown path). List uses the same mask rules and accepts `return_partial_success`, which changes nothing because every local bucket is reachable.

The bucket resource matches the whole Storage v2 UpdateBucket response Cloud Storage returned on 2026-11-17 (case `bkt-gaps-legacy-class-region`, step `grpc-update-bucket-class-regional`) and the whole GetBucket response under the Java SDK's default mask (case `grpc-bucket-unset-settings-mask`), with no ignored fields. Each bucket and default object ACL entry for a team of the bucket's project carries `entity_alt` naming the project ID (`project-owners-{id}`), as object ACL entries do; a team of another project number has none, because gcs-mimic cannot tell which ID that number stands for ([project numbers](project-numbers.md)). `create_time` and `update_time` carry milliseconds, as recorded; the retention and soft delete effective times, the Autoclass times and the uniform access lock time are floored to the millisecond too, the precision JSON renders every bucket time with (inferred, not recorded for Storage v2). A soft delete policy whose duration is 0 has no `effective_time`, as JSON already reported it. Page size defaults to 1000 and is capped at 1000; a negative size answers INVALID_ARGUMENT `The requested page_size must be positive.` with reason `GRPC_PAGE_SIZE_MUST_BE_POSITIVE`, before any read mask is checked, as Cloud Storage did (recorded 2026-11-18). Tokens are opaque project/prefix-bound catalog cursors shared with JSON, not provider-compatible token bytes.

Every Storage v2 RPC requires `x-goog-request-params` and compares it with the
request at the common entry point; a call without it answers INVALID_ARGUMENT with
reason `GRPC_INVALID_X_GOOG_REQUEST_PARAMS`. Cloud Storage was recorded refusing
GetObject, GetBucket, ListBuckets and WriteObject sent without it (case
`grpc-probe-routing`, 2026-11-18); requiring it on the other RPCs generalizes those
four. QueryWriteStatus and CancelResumableWrite are exempt, as recorded: they
answer from the upload ID, read no metadata and route no bucket. A routed bucket
that is not a `projects/_/buckets/<id>` resource name answers INVALID_ARGUMENT with
reason `GRPC_INVALID_X_GOOG_REQUEST_PARAMS_INVALID_BUCKET_FORMAT`, and a routed
bucket other than the request's, or metadata that routes no bucket where the
request names one, answers INVALID_ARGUMENT with reason
`GRPC_INVALID_X_GOOG_REQUEST_PARAMS_BUCKET` naming both bucket IDs (both recorded).
A call reads only the keys it routes: `bucket` (the request's bucket or the
destination bucket), `project` (CreateBucket and ListBuckets), `source_bucket`
(rewrite sources) and `appendable` (writes). Unknown keys, a `routing_token` and
the keys an RPC does not route are ignored, whatever they hold, including Go's
`direct_connectivity_diagnostic` (recorded for an unknown key, a routed project on
GetObject and a `routing_token`). Streaming calls compare the first message and
rewrite continuations compare the token's bound names. Values are
form-percent-decoded; a key routed twice is compared at every value and the first
that disagrees fails. Routing cannot change catalog selection or authorization.
Bucket IDs follow the configured native or fake-gcs-server naming profile in both
bucket and object RPCs. The wording of a conflicting project or appendable value,
a malformed pair under a routed key and a repeated key are local choices (no
recording sent them), as the invalid-name statuses are under
SPEC-GRPC-ROUTING-NAMES; a run of the Go and Rust gRPC SDK lanes against these
checks remains pending.

`x-goog-user-project` is ignored on every Storage v2 RPC, including an empty value, as the JSON API ignores userProject since 2026-11-13 (SPEC-SDK-UNSUPPORTED): a local bucket cannot enable Requester Pays, so the billing project cannot change a result. The default Go client does not send this header, and `Bucket.UserProject` with or without a project is accepted alike. Storage v2 maps storage failures directly to statuses (`src/grpc/v2/status.rs`): a backend failure answers UNAVAILABLE and an unsupported emulator semantic answers ErrorInfo-bearing UNIMPLEMENTED, even where the JSON API answers HTTP 400.

The [pinned Storage v2 proto](https://github.com/googleapis/googleapis/blob/933dd1be8180a22bca2dc473b53d4f4297ee3b0c/google/storage/v2/storage.proto) was retrieved and its SHA-256 matched `a0df6132967b97a89be248f1f24d277ee8df8f8d885db1d4af6249469ff0c1cf` on 2026-10-27. In particular, CreateBucket.parent is empty or projects/_; the owner belongs in bucket.project. A request may name the project by ID or by the number its buckets render, and a ListBuckets page token continues under either spelling (BEHAVIOR-COMMON-014). Storage v1 and object cross-transport semantics are outside this slice.

## Ledger cases

The ledger rows list one acceptance case per checkable behavior (decomposed on 2026-11-18). An answer that was recorded from Cloud Storage on 2026-11-18 is aligned behavior; an answer Google does not document and nothing recorded is a local choice, recorded as a scoped difference with a pinning test. In summary:

- Refused on purpose (scoped differences under SPEC-GRPC-UNMODELED-SETTINGS): the creation settings above that the JSON API does not store either, each with ErrorInfo and without creating the bucket; the `satisfies_pzs` read mask on GetBucket and ListBuckets; and conditional IAM bindings and audit configs on SetIamPolicy.
- Every Storage v2 RPC row depends on BEHAVIOR-RPC-001, because every RPC passes these routing and request-metadata checks; its pending cases below keep each RPC row PARTIAL.
- Declared local choices (SPEC-GRPC-LOCAL-CHOICES unless noted; the recording shows Cloud Storage answering otherwise for the first two): nested bucket read mask paths, refused with UNIMPLEMENTED on GetBucket and ListBuckets; the `*` update mask on UpdateBucket, refused with UNIMPLEMENTED. Other local choices: the creation fields the proto does not mark output only; the answer to a fractional soft delete duration on CreateBucket; the order of DeleteBucket's authorization before its other checks; deleting a bucket whose only object is an unfinalized appendable object; LockBucketRetentionPolicy's refusal of a match of 0 or below, which nothing recorded because the harness never locks a real bucket; the order in which ListBuckets checks its read mask; and the INVALID_ARGUMENT answers for malformed or conflicting routing values (SPEC-GRPC-ROUTING-NAMES).
- Pending code work: nested bucket read masks and the `*` update mask (Cloud Storage serves both); UpdateBucket predefined ACLs; CreateBucket lifecycle, ACLs and predefined ACLs.
- Pending tests: the Go and Rust gRPC SDK lanes for routing.
- Decisions: whether the server enforces `grpc-timeout`; whether gzip message compression is offered.

## Bucket changes on 2026-11-18

Two groups of changes alter answers. The Storage v2 probes recorded against Cloud Storage on 2026-11-18 (cases `grpc-probe-bucket-conditions`, `grpc-probe-bucket-masks` and `grpc-probe-routing`, see the [probe evidence](../evidence/provider-differential-gap-probes.md#twelfth-recording-storage-v2-grpc-probes)) aligned UpdateBucket, DeleteBucket, GetBucket, ListBuckets and the routing metadata. Separately, the proto's own rules changed CreateBucket's rounding of a fractional retention duration and its handling of output-only fields, and the rounding of a retention duration outside the canonical `Duration` form on both RPCs. Existing tests pinned the earlier answers of most of these, and each fix changed those tests together with the code.

- UpdateBucket ignores `bucket.etag`. The proto says that, "If included in the metadata of an `UpdateBucketRequest`, the operation is only performed if the `etag` matches that of the bucket" (storage.proto lines 2581-2584), but Cloud Storage applied updates that named a superseded ETag, the current ETag and a value that is no ETag alike (recorded), so only the request's metageneration conditions make an update conditional (`grpc_bucket_update_ignores_the_bucket_etag`).
- Bucket metageneration conditions are compared as they arrive on GetBucket, UpdateBucket and DeleteBucket, as recorded: a zero or negative match never holds and answers FAILED_PRECONDITION `At least one of the pre-conditions you specified did not hold.`, a zero or negative not-match always holds, and both conditions are evaluated together. A missing bucket answers NOT_FOUND before any condition. LockBucketRetentionPolicy, whose request has only a required match, still refuses 0 and negative values with INVALID_ARGUMENT before the lookup: nothing was recorded for it (`bucket_rpcs_keep_their_own_metageneration_condition_rules`).
- DeleteBucket answers authorization first, then a missing bucket (NOT_FOUND, also when a condition fails), a failed condition and remaining objects, as recorded for the last three; a bucket that still holds objects answers `The bucket you tried to delete is not empty.`, and a not-match that alone fails answers `The resource you requested has not been modified according to the condition you specified.` (`delete_bucket_reports_authorization_existence_conditions_then_contents`). The retained-state rules above are pinned by `delete_bucket_follows_the_shared_catalog_for_retained_state`.
- UpdateBucket paths: a path that names no Bucket field answers INVALID_ARGUMENT with Cloud Storage's wording; an output-only path is accepted and changes nothing (recorded for `create_time` and `update_time`; that the other OUTPUT_ONLY fields behave alike is inferred); an empty or absent `update_mask` answers INVALID_ARGUMENT `Invalid update_mask. Requests should specify at least one update field.` with reason `GRPC_MISSING_UPDATE_MASK_FIELDS` (`output_only_paths_change_nothing_and_unknown_paths_are_invalid`). Each accepted path is parsed once into a typed `UpdatePath` and applied in mask order; it changes only its own setting, and every other path, including `*`, an empty label key, other case spellings, subpaths of the accepted fields and an output-only field named with a member path, answers UNIMPLEMENTED naming the path (`update_mask_paths_select_their_settings_and_refuse_the_rest`). The `*` mask is a declared local choice: Cloud Storage served it as a full replacement.
- A fractional soft delete duration answers INVALID_ARGUMENT `Invalid argument.` with a `BadRequest` on UpdateBucket, as recorded, and CreateBucket answers it alike through a shared helper (`create_rejects_output_fields_and_fractional_durations_in_order`). It used to answer UNIMPLEMENTED.
- A negative ListBuckets `page_size` answers INVALID_ARGUMENT `The requested page_size must be positive.` with reason `GRPC_PAGE_SIZE_MUST_BE_POSITIVE`, even beside an unknown read mask path (recorded).
- GetBucket and ListBuckets answer an unknown top-level read mask path with INVALID_ARGUMENT, and refuse nested paths and `satisfies_pzs` with UNIMPLEMENTED, in each RPC's order (`bucket_read_masks_refuse_unselectable_paths_in_each_rpcs_order`).
- Routing metadata is now required and compared as described above (`grpc-probe-routing`).
- CreateBucket rounds a fractional retention duration down and ignores output-only fields, as described above (`create_bucket_rounds_retention_nanos_down`, `create_bucket_ignores_output_only_fields`); UpdateBucket's rounding is pinned by `grpc_bucket_update_rounds_retention_nanos_down`.
- Both RPCs normalize a retention duration before rounding it down, so a `Duration` whose nanos have the other sign than its seconds or reach a whole second rounds by its value: 3600 seconds and -1 nanos stores 3599, 0 seconds and 1500000000 nanos stores 1, and 1 second and -1 nanos is under one second and answers INVALID_ARGUMENT. Before, the nanos were dropped: the first stored 3600, the second was refused and the third stored 1 (the two rounding tests above).
- Newly pinned refusals: conditional bindings and audit configs on SetIamPolicy (`grpc_iam_set_refuses_conditional_bindings_and_audit_configs`), an empty `website` on CreateBucket, and strict LockBucketRetentionPolicy, which needs `storage.buckets.update` before the lookup (`grpc_retention_lock_requires_bucket_update_permission`).

Still pending on these rows: nested bucket read masks; CreateBucket lifecycle, ACLs and predefined ACLs; an UpdateBucket `*` mask and predefined ACLs; SetIamPolicy masks that name only some policy fields; TestIamPermissions on an object; and the separate `storage.buckets.setIamPolicy` check on UpdateBucket, which no registered caller can reach today because every role granting `storage.buckets.update` also grants `storage.buckets.setIamPolicy`.
