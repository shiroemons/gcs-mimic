## Scope and contract

Checked on 2026-10-23 against the official [copy](https://docs.cloud.google.com/storage/docs/json_api/v1/objects/copy), [rewrite](https://docs.cloud.google.com/storage/docs/json_api/v1/objects/rewrite), [compose](https://docs.cloud.google.com/storage/docs/json_api/v1/objects/compose), [object resource](https://docs.cloud.google.com/storage/docs/json_api/v1/objects), [preconditions](https://docs.cloud.google.com/storage/docs/request-preconditions), [validation](https://docs.cloud.google.com/storage/docs/data-validation), [composite objects](https://docs.cloud.google.com/storage/docs/composite-objects) and [status codes](https://docs.cloud.google.com/storage/docs/json_api/v1/status-codes) contracts.

This slice extends the frozen [basic JSON profile](basic-json-contract.md). It owns JSON-OBJECTS-003 and BEHAVIOR-OBJECT-023. Rewrite continuation and composite-object metadata belong to their own slices.

The official stable Rust manifest dated 2026-10-15 reports `1.99.1 (58cf8f9c3 2026-10-13)`, matching the repository pin. No dependency is added. Serialized MD5 state uses the pinned md-5 0.11.0 format; changing that format requires a catalog migration.

The shared foundation pins each selected generation under catalog serialization by linking its immutable opaque blob into staging. Transfers own up to 32 ordered ranges and persist an output offset; an interrupted write truncates to that offset before resuming. Source deletion, overwrite and catalog restart do not change pinned bytes. Each call uses a 64 KiB buffer and shares the eight-upload admission limit. Separate quotas allow at most 128 continuable transfers and 128 ephemeral copy/compose transfers, for a bounded total of 256; abandoned rewrites cannot consume ephemeral capacity. Injected-clock creation/deadline values fix a seven-day lifetime for continuable transfers and fifteen minutes for ephemeral transfers; the existing maintenance scheduler expires them without polling. Request guards are armed before the blocking begin job and cancel dropped single-call owners after any active writer releases its lease. Recovery validates both quotas, preserves continuable accounting and reclaims ephemeral transfers before readiness.

`resolve_derived_sources` pins all request sources in one catalog snapshot. `begin_derived_ephemeral` marks single-call copy/compose transfers for cleanup during restart; `begin_derived` retains client-continuable transfers. `publish_derived_with_validation` validates sources before destination retirement and invokes a separate completion callback after insertion, inside the same transaction. Its source check/hard-delete helpers permit all-or-nothing compose deletion, including same-name sources. Nullable `component_count` distinguishes composite results; their JSON resources and media headers omit MD5. The shared `json::derived_metadata` helper applies empty-body inheritance or explicit-body replacement for copy/rewrite.

`begin_derived_with_binding` invokes an adapter callback inside transfer creation, so rewrite can persist its source metadata/request binding and exact deadline atomically. Incomplete or transient publication failures preserve progress and restore an output renamed before rollback. Only owned transfer IDs may clean files. Cleanup failures are logged without replacing the original publication result. Recovery discards isolated corrupt transfers, validates the acknowledged prefix against persisted MD5/CRC32C with bounded reads, and continues opening the catalog; missing published-object blobs still fail readiness under the existing durability protocol.

Writable catalog connections enable SQLite foreign keys. Adapter binding tables must reference `derived_transfers(id) ON DELETE CASCADE`; the database then tears down bindings in the same cancel, expiry, quarantine or publication transaction. Maintenance skips busy due transfers, wakes on lease release, tolerates a concurrently removed transfer, and still attempts resumable cleanup when other derived cleanup fails.

Remaining foundation limits: link/create/rename/directory-sync operations hold the catalog execution permit, and recovery checksum verification performs work proportional to acknowledged bytes before readiness. A shutdown interrupts an advance at a buffer boundary; its unacknowledged tail is truncated on retry. Compose adapters must deduplicate deletion targets and define destination-as-source deletion explicitly. A successful publish reclaims its tagged callback deletions outside the write transaction; failures preserve success and stay in the journal for maintenance retry. The internal non-null MD5 column retains a computed digest for composite blobs, but neither JSON resources nor media hash headers expose it as an available MD5 checksum.

JSON literal `null`, including surrounding JSON whitespace, uses the same source-inheritance rule as a zero-byte request body. This is an explicit local interpretation because generated Go JSON clients encode a nil optional resource as `null`. An explicit `{}` currently replaces editable metadata with the modeled destination defaults; the official empty-body wording versus high-level Go zero-value attributes does not establish exact provider behavior for this distinction. Keep it as a named provider-parity question rather than claiming that local SDK success resolves it.

The chosen class rule follows source editable-metadata inheritance for absent/null bodies (`Some(source.storage_class)`); explicit resources without `storageClass` select the destination bucket default (`None`). The resource reference marks storageClass writable, but exact omission/default behavior remains part of the body-parity question. `json::derived_component_count(source, destination_class, same_location)` preserves composite component count in the same location/class and returns one when either differs, following the rewrite reference. Composite identity is separate from editable metadata replacement, so `{}` does not turn a composite into an MD5-bearing non-composite object. Copy checks this against modeled source/destination bucket locations; provider replication/large-object thresholds remain outside the local model.

Copy evaluates source conditions in the catalog snapshot that pins the selected generation. Later source object replacement/deletion does not change those bytes or retroactively fail that selection; publication does not require the pinned generation to remain selectable. Source storage.objects.get is checked at selection and rechecked against the current source bucket policy/project in the publication transaction. Revocation returns 403 without a destination and reclaims the transfer and staging files. This is the local authorization timing contract, not a claim about exact provider race timing. For same-name copy without a destination condition, publication may replace a newer generation written after selection; `ifGenerationMatch` protects the destination independently. Destination conditions, create/delete authority and holds have an advisory check before transfer and an authoritative check in the publication transaction. Composite count uses the class and destination location selected by that transaction, including concurrent default-class changes.

Copy streams in 16 MiB advances through the shared 64 KiB buffer and keeps its request guard in the handler future. The larger advance reduces checkpoint/fsync frequency without increasing the streaming buffer; no throughput improvement is claimed without a recorded benchmark. Its request deadline bounds begin and streaming; cancellation before publication removes the transfer after any active advance completes. Begin and advance mark catalog activity so the connection inactivity watchdog does not silently close a queued request; the request deadline returns its defined error. The catalog wait budget bounds final catalog execution admission, never the whole stream. Once admitted, publication returns its durable outcome instead of returning a timeout while a detached task can still commit. Phase-local upload admission can still reject a later advance/publication under competing load; the request guard cleans this failed single-call transfer. Reserving one slot across every phase is outside the current concurrency guarantee.

Publication syncs the staged file, renames it into the blob directory, then commits the new object and removes the transfer in one catalog transaction. Destination conditions, effective create/delete permissions, live event holds, versioning and bucket defaults are checked in that transaction. Failure cleans staging and probes committed references before reclaiming a blob. Recovery restores a renamed but uncommitted output to staging; committed objects retain their blob and abandoned source links are removed by the normal staging scan.

## Acceptance cases

| Area | Declared behavior and checks |
| --- | --- |
| Source resolution | Live default or explicit positive source generation; all four source conditions against the selected metadata; failed conditions return 412; missing bucket/object return 404. Stable handles preserve selected bytes across concurrent source overwrite/deletion. |
| Streaming | Ordered whole objects or validated byte ranges; empty sources and range boundaries; stop exactly at a byte budget; persisted resume after restart; bounded buffers; incremental MD5/CRC32C, checked before publication. |
| Publication | New monotonic generation and metageneration 1; all four destination conditions, including generation match/not-match 0; failed publication preserves the destination and cleans transfer files. Two concurrent create-if-absent operations have exactly one winner. |
| State interactions | Same-object and cross-bucket writes; destination versioning retains old revisions; event-held destination cannot be replaced; destination default holds apply; source holds do not prevent reading. |
| Authorization | Source storage.objects.get at selection and publication; destination storage.objects.create and storage.objects.delete for replacement; current effective policies are rechecked in the publication transaction. |
| Copy adapter | POST encoded source/copyTo/destination path; sourceGeneration and eight conditions; metadata inheritance and supplied overrides; fields; noAcl response projection; 200 object resource; source bytes are unchanged. |
| Unsupported copy inputs | ACLs, encryption/KMS, requester billing, contexts, retention, temporary holds, advanced object fields and semantic headers are explicitly rejected; no false success. Both projection values render the frozen supported metadata subset; owner/ACL and their additional permission parity remain pending. Unknown/output-only metadata follows the frozen profile's explicit boundary. |
| Provider boundaries | Cross-location/class large-object timeout/413 thresholds and exact error precedence/text require provider evidence. Go high-level CopierFrom uses rewrite; generated JSON Objects.Copy provides this slice's SDK operation. |
