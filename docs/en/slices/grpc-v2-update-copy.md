# Storage v2 updates and derived objects

<!-- markdownlint-configure-file {"MD013": false} -->

Scope: RPC-STORAGE-005–010, RPC-STORAGE-012, RPC-STORAGE-017, RPC-STORAGE-021, RPC-STORAGE-024 and BEHAVIOR-RPC-002. This adapter reuses JSON metadata validation, shared authorization and transactional catalog mutations; it adds no settings or dependencies.

## Acceptance contract

| Case | Required behavior |
| --- | --- |
| grpc_update_masks | Only masked supported bucket/object fields change; other fields survive. An empty or absent update mask and a path that names no field are INVALID_ARGUMENT with Cloud Storage's wording; an output-only path is accepted and changes nothing; other unsupported paths return actionable UNIMPLEMENTED. Generation/metageneration conditions are compared as they arrive and checked atomically with the write. |
| grpc_bucket_settings | JSON-supported labels, versioning, CORS, lifecycle, retention, soft deletion, default event hold and IAM configuration use JSON validation and shared persistence. |
| grpc_iam_config_presence | Under the parent iam_config mask an omitted PAP resets to inherited while an omitted UBLA is kept, as Cloud Storage did for an empty iam_config, a UBLA-only and a PAP-only iam_config on 2026-11-13. Leaf masks such as `iam_config.public_access_prevention` change only their setting. |
| grpc_iam | Policy read/write uses the shared policy store and ETags; TestIamPermissions uses the same strict checks as actual operations. Unsupported conditional/audit policies fail explicitly. |
| grpc_lock | Positive if_metageneration_match is mandatory; shared retention locking enforces conditions and irreversible local lock semantics. |
| grpc_derived | Rewrite streams same/cross-bucket bytes with generation conditions and shared continuation sessions; compose selects generations, checks source/destination conditions and accepts 1–32 sources. |
| grpc_move_restore | Same-bucket move is atomic; soft-deleted generation restore uses shared publication and live destination conditions. |
| grpc_json_interoperation | JSON prepares resources and observes gRPC mutations and bytes; ordinary Go NewGRPCClient high-level calls work with deadlines. |
| grpc_strict | Registered Bearer principals use the shared authorization path; denied mutations leave resources unchanged. |

## Sources and boundaries

The pinned Storage v2 protobuf closure and digests are recorded in the [foundation contract](grpc-v2-foundation.md). Official contract: [Storage v2 RPC](https://docs.cloud.google.com/storage/docs/reference/rpc/google.storage.v2) and [pinned protobuf](https://github.com/googleapis/googleapis/blob/933dd1be8180a22bca2dc473b53d4f4297ee3b0c/google/storage/v2/storage.proto), checked 2026-10-27; Storage SHA-256 `a0df6132967b97a89be248f1f24d277ee8df8f8d885db1d4af6249469ff0c1cf`. Go Storage 1.70.0 is pinned by the existing harness. Existing SPEC-001 flat-namespace move and SPEC-COMPOSE-EDGES provider questions remain open; no cloud resources are used.

## Supported subset

Bucket masks: `acl`, `default_object_acl` ([SDK parity](grpc-v2-sdk-parity.md)), `labels`, `labels.KEY`, `storage_class`, `versioning[.enabled]`, `default_event_based_hold`, `cors`, `lifecycle[.rule]`, `retention_policy[.retention_duration]`, `soft_delete_policy[.retention_duration]`, `iam_config`, `iam_config.uniform_bucket_level_access[.enabled]` and `iam_config.public_access_prevention`. The adapter constructs `BucketMetadataUpdate` directly, using shared label, CORS, lifecycle, class, retention and UBLA validation without JSON bodies. Lifecycle is validated metadata; this slice does not add lifecycle execution. Retention nanoseconds follow the proto's whole-second truncation; a fractional soft-delete duration answers INVALID_ARGUMENT `Invalid argument.` with a `BadRequest`, as Cloud Storage did (recorded 2026-11-18). `*` as the update mask answers UNIMPLEMENTED, although Cloud Storage replaced every setting with it; that is a declared local choice (SPEC-GRPC-LOCAL-CHOICES). A path that names no Bucket field answers INVALID_ARGUMENT `There is no field for this resource named '<path>'.`, and an output-only path such as `create_time` or `update_time` is accepted and changes nothing (recorded for those two). `bucket.etag` is ignored: Cloud Storage applied an update that named a superseded ETag (recorded), so only the request's metageneration conditions are conditions.

Under the parent `iam_config` mask the two settings differ: an empty `public_access_prevention` resets to inherited, while `uniform_bucket_level_access` changes only when its message is present. Cloud Storage answered that mask with an empty `iam_config` by resetting public access prevention to inherited and advancing the metageneration (case `grpc-empty-iam-update`), with a UBLA-only `iam_config` by enabling UBLA and resetting enforced public access prevention to inherited, and with a PAP-only `iam_config` by keeping the enabled UBLA (case `grpc-iam-config-partial-update`), all [recorded 2026-11-13](../evidence/provider-differential-gap-probes.md). Until 2026-11-13 the parent mask merged only present settings. Go Storage 1.70.0 sends this parent path for either individual setting, so a Go `BucketAttrsToUpdate` that names only UBLA resets public access prevention, as Cloud Storage does, and one that names only public access prevention keeps UBLA; the leaf masks `iam_config.uniform_bucket_level_access[.enabled]` and `iam_config.public_access_prevention` change only their own setting. The other supported parent masks have one editable scalar or repeated field: versioning false, an absent retention duration, zero soft-delete duration and an empty lifecycle/CORS list retain their existing reset/replace semantics; read-only lock/effective times are never copied into state. The serialization audit uses pinned [BucketAttrsToUpdate.toProtoBucket](https://github.com/googleapis/google-cloud-go/blob/storage/v1.70.0/storage/bucket.go) and its UpdateBucket field-mask construction.

Every accepted nonempty bucket mask counts as a metadata update, including an empty
`iam_config` parent mask. The latter resets public access prevention, keeps UBLA and advances the
metageneration, as recorded under the resolved SPEC-GRPC-EMPTY-IAM-UPDATE.

Shared bucket validation errors name protobuf fields in gRPC responses, including
Autoclass, lifecycle and retention failures raised by the mutation transaction.
JSON responses retain their existing vocabulary and messages. Locked-retention
guidance uses retention_policy.retention_duration without a JSON body example.

Field-dependent metadata diagnostics carry typed reasons and render adapter field
names without rewriting client values. UpdateObject rejects masks combining
`metadata` and `metadata.KEY` in either order, with guidance to choose one form.
Unsupported IAM roles and principal kinds recommend supported policy inputs;
switching transports does not make those inputs supported. Convenience project
members and JSON project queries share one identifier validator.

Object masks: `metadata`, `metadata.KEY`, the five fixed serving metadata strings, `custom_time`, `temporary_hold` and `event_based_hold`. An output-only path (`create_time` and `update_time` recorded, the other OUTPUT_ONLY fields inferred) is accepted and changes nothing but the metageneration, which advances; the pinned Go SDK sends `create_time` for ordinary empty updates. A path that names no Object field answers INVALID_ARGUMENT `There is no field for this resource named '<path>'.`, and an empty or absent `update_mask` answers INVALID_ARGUMENT `Invalid update_mask. Requests should specify at least one update field.` with reason `GRPC_MISSING_UPDATE_MASK_FIELDS` (all recorded 2026-11-18). `*` alone replaces the editable metadata as a JSON PUT does: Cloud Storage cleared the content language, cache control and custom metadata of an object for a `*` update that carried only a content type, and kept its ACL (recorded; `a_wildcard_mask_replaces_the_editable_metadata_and_keeps_the_acl`). A request that also carries an `acl` or a `retention` applies it as its own path does, and the replacement also releases the holds the request does not set, as the JSON PUT does; neither was recorded. `*` beside another path, contexts, `storage_class` and other masks return UNIMPLEMENTED. `acl` replaces the object ACL and `retention` sets or removes object retention ([SDK parity](grpc-v2-sdk-parity.md)). A bare `metadata` mask merges the request's entries into the stored map and clears the map when the request names none; `metadata.` names the empty key. Cloud Storage did both on 2026-11-17 (case `obj-gaps-empty-metadata-key`), and the pinned Go SDK sends the bare path only with an empty map, to delete every key. A `labels` mask replaces the bucket's whole label map; no recording covers it. These changes apply in the shared mutation transaction without adding preconditions; explicit client preconditions remain enforced. Key-level mutations merge individual entries in that transaction.

UpdateObject ignores the `etag` in its object. The proto says of `Object.etag` (lines 2902-2906) that, "If included in the metadata of an update or delete request message, the operation is only performed if the etag matches that of the live object," but Cloud Storage applied an update that named a superseded etag and one that named the current etag alike (recorded 2026-11-18), so only the request's generation and metageneration conditions make an update conditional (`update_object_ignores_the_request_etag`).

UpdateObject constructs `ObjectMetadataUpdate` directly, including typed ACL and
nanosecond retention values. WriteObject, ComposeObject and RewriteObject share
the proto metadata conversion and shared validation. Rewrite still stores its
existing token-binding representation for compatibility, but never reparses it
through the JSON metadata parser when applying a new request.

Generation and metageneration conditions are compared as they arrive, as Cloud Storage answered (case `grpc-probe-object-conditions`, recorded 2026-11-18). UpdateObject, ComposeObject (its destination takes only the two match conditions), RewriteObject (destination and source) and RestoreObject evaluate a metageneration match of 0, which no object holds, as FAILED_PRECONDITION `At least one of the pre-conditions you specified did not hold.`, and a match beside a not-match as one pair; a not-match that names the current value answers FAILED_PRECONDITION `The resource you requested has not been modified according to the condition you specified.`, a rewrite source included. RestoreObject in a bucket without a soft delete policy answers its BadRequest `bucket soft delete policy must be set.` before it reads any condition. MoveObject compares a metageneration match of 0 but refuses a match beside a not-match, for the destination and the source, with INVALID_ARGUMENT and a `BadRequest` `Found conflicting object preconditions. Mutually exclusive fields cannot be set simultaneously.`; that was recorded for pairs naming the same value, and refusing every such pair by its shape is an inference. A negative generation or metageneration condition on an object RPC still answers INVALID_ARGUMENT `Preconditions must be nonnegative; use if_generation_match=0 to create only`; no object recording sent one (`move_object_refuses_condition_pairs_and_failing_conditions_without_moving`, `update_object_refuses_malformed_and_unmodeled_requests_without_changing_the_object`). LockBucketRetentionPolicy keeps its strict rule, a positive `if_metageneration_match`, and has no recording. JSON's broader combined-condition precedence remains outside this scoped RPC acceptance.

IAM supports bucket resources, unconditional predefined-role policies, versions 0 through 3 and opaque shared policy ETags. SetPolicy constructs the shared typed policy input directly and accepts its absent/empty default mask or `bindings,etag`; other masks, conditions, audit configs and managed-folder/object resources remain unsupported. TestPermissions validates the supplied permission strings directly, deduplicates them in request order and retains per-permission authorization, including project grants, bucket grants and PAP. Its input is bounded by the gRPC message limit rather than the JSON query-string limit. Permission evaluation still makes per-permission catalog calls; batching those decisions is deferred to an authorization-layer change. Locking requires a positive matching metageneration and uses shared irreversible emulator-local state.

Rewrite inherits or replaces the JSON-supported editable metadata subset, selects source generations and applies source/destination conditions. Same-location/class copies finish in one call; changed location/class uses the shared 8 MiB default budget or a positive whole-MiB caller budget. Token-only continuation, mismatched-request rejection and last-token replay use the shared durable session. Completed gRPC responses are stored as protobuf bytes inside the existing bounded response envelope; continuation tokens must stay on the gRPC transport. Cross-transport token reuse is not supported. No body bytes are collected: the shared engine stages and copies with a fixed 64 KiB buffer.

Compose accepts 1–32 same-bucket generation-selected sources, source generation-match conditions, destination generation/metageneration-match conditions and the shared optional source-deletion behavior. A canned destination ACL, `temporary_hold` and `custom_time` apply to derived objects as on their JSON counterparts, and ComposeObject and RewriteObject verify `object_checksums` against the object they would write (see the 2026-11-17 notes below); KMS keys, a destination `retention` and a destination `acl` listing entries remain unsupported (UNIMPLEMENTED). A ComposeObject destination `storage_class` equal to the sources' class is accepted and a different one is refused with INVALID_ARGUMENT and a `BadRequest` `Cannot compose object with destination storage class NEARLINE from source components that have different storage classes (STANDARD).`; fields only the service sets (generation, metageneration, size, create and update time and the other OUTPUT_ONLY fields) are ignored (recorded 2026-11-18 for the five named in the case, the rest inferred; `compose_object_accepts_the_sources_class_and_ignores_service_set_fields`). A RewriteObject destination that carries service-set fields is refused with INVALID_ARGUMENT `You must specify an object name.` and a `BadRequest` (recorded for a generation, metageneration, size and both times together), and one that lists `acl` entries answers UNIMPLEMENTED, because publication gives the object the default or a canned ACL; Cloud Storage applied both, so the two ACL refusals are declared local choices (SPEC-GRPC-LOCAL-CHOICES). Customer-supplied keys on compose, rewrite and update follow [grpc-v2-customer-supplied-keys.md](grpc-v2-customer-supplied-keys.md). Shared object-size limits, checksums and publication conditions remain enforced. Move and restore retain the same flat-namespace, retention, versioning and soft-delete semantics as JSON. HNS restore tokens and copying source ACLs remain unsupported. Empty common encryption parameters, empty request-level checksum messages and false ACL flags have their default meaning.

No setting is added. The gRPC service receives the existing `max_object_bytes` setting so copies/compositions honor the same configured body cap as JSON. Shared storage and startup ordering are unchanged. Every broad ledger row remains PARTIAL because these explicit unsupported cases and broader provider parity remain open.

Storage v2 maps the storage domain errors directly to statuses (`src/grpc/v2/status.rs`), without going through the JSON adapter: an expired rewrite session answers FAILED_PRECONDITION and an unsupported setting UNIMPLEMENTED with ErrorInfo. Foundation fail-fast checks use unsupported Rapid writes; CancelResumableWrite is implemented in the [object I/O contract](grpc-v2-object-io.md). The bucket and object I/O implementations and their configured size limit remain shared.

UpdateBucket, UpdateObject and TestIamPermissions retain LOCAL_SIMULATION achieved fidelity, matching their shared JSON operations; the remaining delivered scopes have EXACT achieved fidelity with explicit pending cases. This does not turn local principals, policy propagation or lifecycle metadata into Google infrastructure.

## Ledger cases

The ledger rows list one acceptance case per checkable behavior (decomposed on 2026-11-18). An answer that Google does not document and the recording of 2026-11-18 did not cover is a local choice, recorded as a scoped difference with a pinning test. In summary:

- Refused on purpose (scoped differences under SPEC-GRPC-UNMODELED-SETTINGS): UpdateBucket paths for settings the JSON API does not store either (`rpo`, `website`, `logging`, `encryption`, `billing`, `custom_placement_config`, `hierarchical_namespace`, `ip_filter`, `satisfies_pzs`), each pinned with its ErrorInfo; UpdateObject `contexts` and `contexts.custom` paths; ComposeObject `kms_key` and RewriteObject `destination_kms_key`; managed-folder IAM resources on GetIamPolicy, SetIamPolicy and TestIamPermissions; RestoreObject `restore_token`, which only hierarchical namespace buckets use.
- Declared local choices (Cloud Storage answered otherwise on 2026-11-18, SPEC-GRPC-LOCAL-CHOICES): UpdateBucket's `*` update mask and nested bucket read masks are refused with UNIMPLEMENTED; a destination `acl` on ComposeObject and RewriteObject is refused with UNIMPLEMENTED; GetIamPolicy on an object resource answers UNIMPLEMENTED, because Cloud Storage renders the object's ACL as a policy and gcs-mimic keeps no object policy.
- Other local choices (SPEC-GRPC-LOCAL-CHOICES): SetIamPolicy on an object resource answers UNIMPLEMENTED, because the proto names only bucket and managed-folder resources for it; a stale policy etag, or a malformed one that is not the eight bytes every issued etag has, answers FAILED_PRECONDITION; CreateBucket's answer to a fractional soft delete duration, shared with the recorded UpdateBucket answer; UpdateBucket's implicit lifecycle check retries three times and then answers ABORTED, when the request carries no metageneration condition; UpdateObject refuses a `storage_class` update path, which the proto does not describe and a JSON metadata update does not apply either: the JSON adapter refuses a changed `storageClass` as an unsupported setting and accepts only a repeated equal value. Locking a bucket without a policy, or twice, answers INVALID_ARGUMENT (SPEC-RETENTION-POLICY). RestoreObject refuses a customer-supplied key (SPEC-GRPC-CSEK) and answers with owner and ACL (SPEC-GRPC-DERIVED-OWNER-VIEW).
- Pending code work: `*` update masks on UpdateBucket; UpdateBucket predefined ACLs, which Cloud Storage and the JSON PATCH apply; SetIamPolicy masks that name only some policy fields; TestIamPermissions on an object, which the proto documents and Cloud Storage serves; destination `retention` and `acl` on ComposeObject and RewriteObject; RestoreObject `copy_source_acl`.
- Pending tests: the separate `storage.buckets.setIamPolicy` check for public access prevention and ACL changes; ComposeObject's `storage.objects.get` and overwrite `storage.objects.delete` permissions; the owner view of a canned-ACL ComposeObject for a caller without ACL read permission; a rewrite token used on the other transport.
- Decisions: whether a rewritten object keeps the source's content type, which Cloud Storage's recorded completed rewrites did not carry; MoveObject's permission set, which checks `storage.objects.get`, `.delete` and `.create` as the JSON move does where the proto lists `storage.objects.move`, `.create`, and `.delete` only when overwriting. Bucket and object conditions follow Cloud Storage's recorded answers (see above); only LockBucketRetentionPolicy and a negative object condition keep a local refusal.

GetIamPolicy (RPC-STORAGE-006) has no pending case of its own. Like every Storage v2 row it depends on BEHAVIOR-RPC-001, because every RPC passes its routing and request-metadata handling, so it stays PARTIAL while that row's routing SDK lanes, server-side `grpc-timeout` and gzip message compression are pending.

Also on 2026-11-17, request checksums on ComposeObject and RewriteObject were aligned with a new recording (case `grpc-gaps-derived-checksums`, see the [gap probe evidence](../evidence/provider-differential-gap-probes.md#sixth-recording-storage-v2-request-checksums-on-derived-writes)) and the two wrong-checksum markers were removed. ComposeObject checks a declared CRC32C against the CRC32C combined from its sources before any byte is read and refuses any MD5 with INVALID_ARGUMENT `Invalid argument.`, because a composite object has none. RewriteObject refuses an MD5 that is not 16 bytes with `Provided value (<base64>) is not a base64-encoded 128-bit MD5 hash.`, then checks the declared CRC32C and MD5 against the source's stored hashes before a session starts; the token binds them after `destinationPredefinedAcl`, so a continuation that repeats other checksums is refused as a token mismatch. A mismatch answers INVALID_ARGUMENT with Cloud Storage's CRC32C or MD5 message and a `BadRequest` repeating it, CRC32C first, and writes nothing. A rewrite whose source shows no MD5, such as a composite object, refuses a declared MD5 with `Invalid argument.` as a compose does (inferred). Unlike a JSON rewrite, which ignores a supplied `md5Hash`, the Storage v2 rewrite checks it, as Cloud Storage did. Bytes that fail the digests recorded for their source are reported as damaged storage (UNAVAILABLE), never as a checksum the client specified. `grpc_derived_writes_verify_request_checksums`, `grpc_rewrite_tokens_bind_declared_checksums` and `rewrite_tokens_bind_the_stored_parameter_spelling` pin this. Cloud Storage answered the completed rewrites in that case without the source's `contentType`, which gcs-mimic copies; when Storage v2 drops it remains open.

On 2026-11-18 the probes recorded in case `grpc-probe-object-masks` showed that Cloud Storage applies an UpdateObject whose `etag` an earlier update had superseded, so UpdateObject ignores the request etag. `update_object_ignores_the_request_etag` in `src/grpc/v2/update_object/object_etag.rs` pins it: updates that name the current etag, a superseded one, a made-up one and none all apply and advance the metageneration. The earlier behavior, which refused a mismatching etag with FAILED_PRECONDITION and compared the etag of a selected generation, was removed together with its tests. No SDK suite or provider request was run for this change.

- `update_object_refuses_malformed_and_unmodeled_requests_without_changing_the_object`: a missing object or update_mask, a negative generation, a negative condition and a retention without a mode or without `retain_until_time` answer INVALID_ARGUMENT, a metageneration match of 0 and a match beside a not-match answer FAILED_PRECONDITION as Cloud Storage did, a path that names no object field answers INVALID_ARGUMENT, and the `contexts`, `contexts.custom` and `storage_class` paths and `*` beside another path answer UNIMPLEMENTED with ErrorInfo.
- `compose_object_refuses_malformed_and_unmodeled_requests_without_creating_the_destination`: a missing destination and a negative source generation or source condition answer INVALID_ARGUMENT; a destination retention, KMS key or explicit ACL answers UNIMPLEMENTED; a metageneration match of 0 answers FAILED_PRECONDITION and a destination storage class other than the sources' answers INVALID_ARGUMENT with a `BadRequest`, both as recorded.
- `rewrite_object_refuses_malformed_and_unmodeled_requests_without_creating_the_destination`: a negative source generation, a negative source condition, a budget that is negative or not a whole MiB, a destination naming its bucket or name, a malformed token and a destination carrying service-set fields answer INVALID_ARGUMENT; a metageneration match of 0 and a source match beside a not-match answer FAILED_PRECONDITION as recorded; a destination resource KMS key answers UNIMPLEMENTED.
- `restore_object_refuses_a_missing_generation_and_copying_the_source_acl`: a missing or negative generation answers INVALID_ARGUMENT; `copy_source_acl` true and a `restore_token` answer UNIMPLEMENTED for a soft-deleted source and restore nothing; `copy_source_acl` false restores.

The `*` mask on UpdateBucket, destination retention and ACLs and `copy_source_acl` stay pending code work, as listed under [Ledger cases](#ledger-cases).
