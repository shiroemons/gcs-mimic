# 0.18.0 public contract changes

<!-- markdownlint-configure-file {"MD013": false} -->

Draft release notes for the contract changes before the 1.0.0 freeze.

## Ready event fields

The ready event drops two fixed fields and identifies the opened disk catalog.

| Before | From 0.18.0 | Required edit |
| --- | --- | --- |
| `protocol: "http1"` | Absent | Remove the lookup or assertion; no replacement field is added. |
| `gcs_api: "json-bucket-object-media-crud"` | Absent | Remove the lookup or assertion; no replacement field is added. |
| No data directory fields | Disk: absolute `data_dir` and `data_dir_state: "created"` or `"opened"`; memory: both absent | Read the optional pair to identify the store. Do not require them for memory mode. |

For example, inspect the selected store from JSON Lines output:

```sh
jq 'select(.event == "ready") | {data_dir, data_dir_state}' server.log
```

A pre-existing directory without an initialized catalog, including an empty database left by an interrupted first open, counts as `created` when this start initializes it. Once initialization commits, a subsequent start reports `opened` even if the previous process crashed before its first ready event. The path is made absolute from the working directory without resolving symbolic links. The native default remains `data`; the container's default is unchanged.

Creation also emits one info-level `data_dir_created` event on stderr with the absolute `data_dir` and a message naming it. Existing catalogs and memory mode emit none; `log_level` filters it like other runtime info events. See the [startup contract](../slices/startup-phases.md) and [verification](../evidence/ready-event.md).

## Environment variable names

The server reads `GCS_MIMIC_*`; every other program in this project reads `GCSM_*`.
The server still stops on an unknown setting and ignores every `GCSM_*` name,
so applications and the emulator can safely share an environment file.

| Old name | New name | Used by |
| --- | --- | --- |
| `GCS_MIMIC_ENDPOINT` | `GCSM_ENDPOINT` | Client examples and SDK harnesses |
| `GCS_MIMIC_GRPC_ENDPOINT` | `GCSM_GRPC_ENDPOINT` | Rust client example and SDK harness |
| `GCS_MIMIC_SYNC_TOKEN` | `GCSM_SYNC_TOKEN` | `gcs-mimic sync`; `--token-file` takes precedence |
| `GCS_MIMIC_BINARY` | `GCSM_BINARY` | Go subprocess package |
| `GCS_MIMIC_PORT` | `GCSM_PORT` | Compose host port publication |
| `GCS_MIMIC_IMAGE` | `GCSM_IMAGE` | Compose image selection |
| `GCS_MIMIC_TLS_DIR` | `GCSM_TLS_DIR` | Compose certificate mount selection |

Rename these variables in shell exports, shared `.env` files and Compose
invocations. There is no compatibility fallback: an old name never supplies a
value. The server rejects each old name with its replacement. The sync CLI
rejects its old name even when empty, a new token is set or `--token-file` is
supplied. The Go package and examples reject their old name when no replacement
or explicit option supplies the value.

Repository test, script and SDK harness variables also move from `GCS_MIMIC_`
to `GCSM_`. The signed-browser script's former `BIN` suffix merges into
`GCSM_BINARY`; all other suffixes stay unchanged. Server setting names are unchanged.
Documentation checks derive allowed names from `Setting`; only deliberately
rejected migration and unknown-setting inputs, plus explicitly baselined
historical records, remain outside that set.

SDK runners and the Go package still remove inherited server settings before
starting their isolated, explicitly configured children. This prevents a
developer shell from altering a test scenario; client variables need no removal.

Compose interpolation alone does not reject an obsolete variable: without a
matching reference, Compose would silently use its default image and port.
The shipped Compose files therefore pass the three old Compose names into the
server only when set, so startup fails with replacement advice instead of
using an unintended default. Rename them in your shell and `.env` even if a
new name is also set. The TLS overlay also requires `GCSM_TLS_DIR` explicitly.

## fake-gcs-server flags

Source flags now either preserve working requests or stop startup with the native
alternative. Accepted translations emit one `info` diagnostic containing all
native options in the canonical `native_args` JSON string array. A shell line
is shown only when values contain no quotes, backslashes or control characters;
otherwise decode the array and pass its elements as arguments. Paths and
identifiers are preserved; only unsafe URLs are redacted. `log_level=warn` or `error` hides that
info block; validation warnings and errors always remain visible.

| Before | In 0.18.0 | What to edit |
| --- | --- | --- |
| `--filesystem-root /storage` was ignored with a warning | Refused | Choose `--data-dir PATH` (`/var/lib/gcs-mimic` in the image); convert a stopped source snapshot with `gcs-mimic import fake-gcs-server` |
| `--external-url URL` became `api_base_url`, also fixing resumable URLs | Refused | Choose `--api-base-url URL` with an address every client can reach |
| `--public-host HOST` selected a public origin | Accepted with routing advice | JSON API callers must use a host outside public-host subdomains or set `--api-base-url` explicitly |
| `--cors-headers HEADERS` discarded the list and selected `allow-all` | Refused in every auth mode | Remove it, or explicitly use `--cors-fallback allow-all` for XML/public buckets without rules |
| `--location LOCATION` became a creation-only default | Refused | Use native `--default-location LOCATION`; existing buckets and explicit locations win |
| `--event.*` could reach native validation without a local host | Every flag requires a local Pub/Sub emulator host | Set `PUBSUB_EMULATOR_HOST` or native `pubsub_emulator_host`; complete project/topic settings remain required |
| `--event.list none` disabled the global rule | Refused because the source has no such selection | Use native `--event-list none` |
| `--port-http N` outside `scheme=both` was ignored with a warning | Startup fails | Add `--scheme both` or remove the unused port |
| Accepted source flags could be silent or warn about a semantic difference | One native-equivalent info block; inexact flags fail together | Use the emitted native settings; resolve every refused flag before restarting |

`--host`, `--port`, `--port-http`, `--scheme` and `--log-level` are native
serve options. `--backend filesystem`, `--public-host`, `--data`,
`--cert-location` and `--private-key-location` retain their documented native
translations; `--backend memory` is already native.
See the [complete flag table](../slices/option-aliases.md#behavior).

Permissive mode already allows every origin on XML/public buckets without
rules. Strict mode follows each bucket's CORS rules; stored rules remain exact
even with explicit fallback. JSON preflight continues to allow every valid
requested header. The scheme default remains `https` in this release.
