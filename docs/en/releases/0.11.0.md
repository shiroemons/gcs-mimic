# gcs-mimic 0.11.0

0.11.0 makes the container image about 70% smaller: it now ships a statically linked musl binary on an empty `scratch` base instead of a glibc binary on Distroless. Server behavior, configuration and the catalog schema are unchanged from 0.10.0. Images that build on top of the gcs-mimic image or rely on files from the old base should read [Compatibility and migration](#compatibility-and-migration) before upgrading.

It publishes `ghcr.io/shiroemons/gcs-mimic:0.11.0` for `linux/amd64` and `linux/arm64`, mirrors the same digest to Docker Hub as `shiroemons/gcs-mimic:0.11.0`, and publishes native archives for all eight macOS, Windows and Linux targets. The [feature matrix](../feature-matrix.md) lists the exact supported subsets. Rows marked `PARTIAL` keep their listed missing cases.

## Changes

### Container image

- The image starts from `scratch` and contains the `gcs-mimic` binary, its license notices under `/usr/share/licenses/gcs-mimic`, the data directory owned by UID/GID 10001 and a sticky `/tmp`. The binary links only libc statically and embeds its TLS trust store, so it needs no C library, CA bundle, time zone data or user database from the base image.
- The container binary is built for musl with fat LTO and `opt-level = "s"`. The native release archives keep their default build profile.
- Local measurements of the release candidate: about 28 MB uncompressed and 8.1 MB compressed on `linux/amd64` (0.10.0: 92.8 MB and 20.4 MB), and about 26 MB and 7.9 MB on `linux/arm64` (0.10.0: 100.7 MB and 20.6 MB). See the [scratch runtime evidence](../evidence/scratch-runtime.md).
- The user, entrypoint, default command, environment defaults, exposed port, health check and stop signal are unchanged.

### License notices

- Release archives and the image include the Rust standard library's `COPYRIGHT-library.html` and its license texts instead of the toolchain-wide `COPYRIGHT.html`, because no compiler or tool component ships. The image adds the musl source archive that the musl native archives already carried.

### Dependencies and project

- The container build installs `musl-tools` from the Debian snapshot the pinned Rust image was built from, and the release freshness check now compares that package. The Distroless runtime input is removed.
- The Rust builder image digest, the Go API client v0.311.0, genproto and Bundler 4.0.24 in the SDK suites are refreshed; the Rust toolchain stays 1.99.1.
- Tests wait for observable state instead of wall-clock delays, a production lint ratchets new wall-clock calls in test code, and a daily CI job runs the Rust tests under CPU stress.

## Compatibility and migration

0.11.0 keeps catalog schema 50 from 0.10.0, so a data directory moves between the two releases in both directions. The server binary's API behavior is unchanged.

### Upgrade checklist

- **Derived images.** The old base supplied `/etc/passwd`, `/etc/group`, CA certificates under `/etc/ssl`, time zone data and Debian package records; the new image has none of them. An image built `FROM` gcs-mimic that copies in tools needing those files must now provide them itself. The image has never contained a shell.
- **Process user.** The process still runs as numeric UID/GID 10001, so existing data volumes stay writable. The old base's named users (such as `nonroot`, UID 65532) no longer exist; refer to users by numeric ID.
- **Temporary files.** `/tmp` exists with mode 1777. With `--read-only`, mount a writable `tmpfs` at `/tmp` when running imports that spool there, as before.

### Behavior changes in detail

- Throughput of many small concurrent requests is lower than with the glibc build because of musl's allocator: a short local run measured about 6,000 against 8,000 small GETs per second on two CPUs, while large transfers and resident memory (about 12 MiB against 16 MiB idle after the run) did not regress.

## Known limitations

- The `linux/amd64` image was smoke-tested locally only under emulation before the release; the release workflow builds and smoke-tests both architectures natively.
- The container build depends on `snapshot.debian.org`, which intermittently answers 503 or 504 under load; apt retries eight times with backoff.
- The examples under `examples/` and the Go and Ruby scorecard manifests are not run by CI or covered by daily dependency update detection, and still pin the previous Go API client and Bundler.
- The limitations listed for [0.10.0](0.10.0.md#known-limitations) still apply, and these changes do not close the [1.0.0 gate](../release-policy.md#the-100-gate).

## Verification

The [release workflow](https://github.com/shiroemons/gcs-mimic/blob/v0.11.0/.github/workflows/binaries.yaml) creates this Release only after `validate`, including the dependency freshness check, Foundation and all eight native build/test jobs succeed at the tag's SHA. The [container workflow](https://github.com/shiroemons/gcs-mimic/blob/v0.11.0/.github/workflows/ghcr.yaml) then builds both Linux architectures natively, verifies their SBOM and provenance, publishes the multi-architecture tag and checks anonymous pulls, and the Docker Hub workflow mirrors that digest.

Before the release commit, `just pre-push` ran locally on macOS. The Rust and shell checks (format, Clippy, the production lint with no violation on the host and the Windows and Linux targets, the Rust test binaries and doctests, the compatibility ledger check with 606 rows and the documentation checks) and the pinned Go, Ruby, Node.js, Python, PHP, Java, .NET and Rust SDK suites passed, and the `linux/arm64` container smoke test passed every section. The emulated `linux/amd64` smoke test failed in that run while the Docker host was shared with other work; an earlier run the same day on this container source passed every section, and the release workflow's native `linux/amd64` run is the deciding check. `just check-dependencies` reported all 118 tracked inputs current.
