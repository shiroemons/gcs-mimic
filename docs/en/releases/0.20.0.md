# gcs-mimic 0.20.0

0.20.0 ships the last breaking changes that the [public contract review](../public-contract-review.md) decided before the 1.0.0 freeze. They change names, a default and checks between gcs-mimic's own parts, and none has an alias: each withdrawn name or value stops startup with a diagnostic that names its replacement, so a configuration written for an earlier release fails visibly instead of losing its effect. Read [Breaking changes](#breaking-changes) before upgrading; the [upgrade checklist](#upgrade-checklist) lists what to edit.

The [design](../slices/contract-cleanup.md) records the decisions and acceptance cases. The [feature matrix](../feature-matrix.md) lists the exact supported subsets.

## Breaking changes

### A buckets file reconciles existing buckets, and the mode is `buckets_mode`

The buckets document is the source of truth for what its entries write, whether it comes from `buckets_file` or inline from `buckets`. A file used to default to `create` only because it always had.

| If you | 0.19.x | 0.20.0 | What to edit |
| --- | --- | --- | --- |
| Start an existing volume with a buckets file and no mode | Kept existing buckets; warned about edited entries | Applies the fields each entry writes; undoes API changes to them | Set `buckets_mode=create` to keep the old behavior |
| Set `buckets_file_mode` | Selected the mode | Stops startup | Rename it `buckets_mode` |
| Read the ready field `buckets_file` | Initialization counts | Absent | Read `buckets` |

Members an entry does not write keep their API values in both modes, and a location never changes. A written `iamPolicy` is judged against the stored public access prevention in both modes, so a start that wrote nothing in `create` mode can stop in `reconcile` mode.

### `connection_timeout_ms` is removed

It set `header_read_timeout_ms`, `body_inactivity_timeout_ms` and `request_timeout_ms` to one value, the single timeout of releases before 0.12.0. It now stops startup and names the three settings; set them instead.

### Server options take hyphens only

`--max_connections 10` started the server only because the parser treated `_` like `-`. An underscore spelling of a server option now stops startup and names the hyphenated option. Environment variables and JSON keys keep their underscores.

### `backend=filesystem` is a flag translation only

fake-gcs-server's `-backend filesystem` still starts the disk backend. The same value from `GCS_MIMIC_BACKEND` or the JSON file now stops startup and names `disk`.

### `compat_profile=legacy-emulator` is now `fake-gcs-server`

The profile keeps its behavior under a name that says which emulator it follows. The old value stops startup and names the new one.

### `gcs-mimic sync` and the server must be the same release

Each side sends its version in `x-gcs-mimic-version`. A server answers a command of another release, or one without a version, with 400 `versionMismatch` before authentication; the command refuses an answer from another release, or without a version, after printing it. A server before 0.20.0 sends no version, so a 0.20.0 command notices only after that server handled the request; inspect `sync status` before retrying a mutation. `sync approve` also refuses `--revision`; use `--deletion-set`.

### The Go package needs a binary of its release

`go/fakestorage` reads `version` from the ready event and refuses a binary of another minor release with `*UnsupportedBinaryError`, which names the path and both versions. When a binary exits before ready, the package asks `--version` and reports a mismatch as the cause. Build the executable from the same checkout.

## New behavior

- Every withdrawn setting name and value is refused from the command line, the environment and the JSON file alike, and the diagnostic names the replacement as that source spells it, such as `--buckets-mode`, `GCS_MIMIC_BUCKETS_MODE` or `buckets_mode`.
- The [release policy](../release-policy.md) lists the diagnostics members and `source` values, the derived authentication defaults, the on/off spelling rule and the meaning of the `latest` and major container tags. Tests pin the response keys of the user-facing emulator routes, the 64 KiB body they accept, every ready field set and the helper help texts.

## Compatibility and migration

The catalog schema is unchanged at 53, so a data directory moves between 0.19.x and 0.20.0 in either direction without a migration. The first start of an existing volume with a buckets file may change buckets, as described above; a backup of the data directory restores the earlier state.

### Upgrade checklist

- **Buckets files on existing volumes.** Decide whether the file or API changes win. Leave the mode unset for the file, or set `buckets_mode=create` for the API.
- **Renamed settings and values.** Replace `buckets_file_mode` with `buckets_mode`, `connection_timeout_ms` with the three timeouts, `compat_profile=legacy-emulator` with `fake-gcs-server`, and `backend=filesystem` in the environment or JSON with `disk`.
- **Command lines.** Write server options with hyphens.
- **Ready-event readers.** Read `buckets` instead of `buckets_file`.
- **Synchronization scripts.** Use `gcs-mimic sync` from the server's release and `approve --deletion-set`.
- **Go tests.** Point `GCSM_BINARY` or `Options.Executable` at a binary built from the package's checkout.

## Known limitations

- DESIGN-103 stays `PARTIAL` until the container, SDK and release gates run on the release source; the [verification record](../evidence/contract-cleanup.md) lists what has run.
- After 1.0.0 a covered name is deprecated with a warning before it is removed; none of the changes here had that period, by the decision for `0.x`.
- The limitations listed for [0.19.0](0.19.0.md#known-limitations) still apply, and these changes do not close the [1.0.0 gate](../release-policy.md#the-100-gate).
