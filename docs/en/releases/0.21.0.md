# gcs-mimic 0.21.0

0.21.0 aligns about thirty JSON, XML and gRPC behaviors with Cloud Storage. Each one was recorded against the real service on 2026-11-13 and differed in 0.20.1. Most of them make gcs-mimic accept a request it refused, or answer the way Cloud Storage does where it gave another status. A few refuse input that 0.20.1 accepted, so read [What may need attention](#what-may-need-attention) before upgrading. No command, option, environment variable or machine-readable output changes.

It publishes `ghcr.io/shiroemons/gcs-mimic:0.21.0` for `linux/amd64` and `linux/arm64`, mirrors the same digest to Docker Hub as `shiroemons/gcs-mimic:0.21.0`, and publishes native archives for all eight macOS, Windows and Linux targets. The [feature matrix](../feature-matrix.md) lists the exact supported subsets.

## What may need attention

- **Not-match conditions on writes answer 304.** When `ifGenerationNotMatch` or `ifMetagenerationNotMatch` names the current value, an object patch, update, delete, media upload or copy destination now answers 304 with an empty body. Bucket PUT and PATCH do the same with `ifMetagenerationNotMatch`. 0.20.1 answered 412. Nothing is written in either case, and a failing match condition still answers 412 first. gRPC still reports `FAILED_PRECONDITION`.
- **Soft delete retention is capped at 90 days.** A `retentionDurationSeconds` above 7776000 is refused with Cloud Storage's message. This applies to the JSON API, gRPC, the buckets file and the server default. The local acceptance of durations below seven days is unchanged.
- **An empty JSON bucket location is refused.** `"location": ""` on bucket creation answers 400 `The specified location constraint is not valid.` An omitted or null location still uses the default, and so do the buckets file and an empty XML `LocationConstraint`.
- **A resumable chunk past its declared total fails the session.** After a chunk such as `bytes 0-9/5`, every later request on that session answers 400 `Failed to parse Content-Range header.` and no object is created.
- **gRPC `iam_config` parent updates follow Cloud Storage.** An `UpdateBucket` with the `iam_config` mask resets public access prevention to `inherited` when the message leaves it out. Uniform bucket-level access changes only when its message is present. The Go client sends this mask for either setting, so setting only uniform access through it now resets public access prevention, as it does on Cloud Storage.
- **A gRPC `ReadObject` read mask must include `checksummed_data.content`.** Without it, the read answers `INVALID_ARGUMENT` with the `GRPC_READ_MASK_MISSING_CHECKSUMMED_DATA` reason. A request with no mask, an empty mask or `*` is unaffected.
- **Object list page tokens changed format.** A token issued by 0.20.1 is refused as invalid after the upgrade; restart that listing from the first page.

## Changes

### JSON API requests

- Object methods ignore an undeclared query parameter: insert, get, download, patch, update, copy, rewrite, compose and object ACL list. Compose also ignores `ifGenerationNotMatch` and `ifMetagenerationNotMatch`, which it does not declare.
- `fields` follows Cloud Storage's edges on object resources:
  - a whitespace-only selector returns `{}`;
  - spaces around names are trimmed;
  - `metadata()` returns `{}`;
  - `alt=media` ignores `fields`.
- Object and bucket listings ignore `If-None-Match` and `If-Match`.
- Media on the `/download/storage/v1` endpoint carries the same past `Expires` as the ordinary media route.

### Object metadata, copies and composition

- A PATCH body's `generation` selects that generation when the query names none, and a missing one answers 404.
  - `size` and `md5Hash` in a PATCH or PUT body are ignored.
  - A PATCH can store an empty `contentLanguage`, `contentDisposition`, `contentEncoding` or `cacheControl`.
  - A body `name` or `bucket` that disagrees with the path is refused with Cloud Storage's message.
- Copy and rewrite inherit the source metadata when the body is blank, `null`, `{}`, `{"metadata": null}` or `{"metadata": {}}`. 0.20.1 refused the blank body and dropped the inherited fields for the others. Rewrite ignores a supplied `md5Hash`.
- Compose creates the destination at the path name, ignores the output-only `generation` and `size`, and refuses a destination class its sources do not share with Cloud Storage's message.

### Uploads and media

- A multipart media part with `Content-Transfer-Encoding: base64` is decoded as it streams. A non-JSON third part and a body without its closing delimiter answer with Cloud Storage's errors.
- An object stored as `application/gzip` with `Content-Encoding: gzip` is always served gunzipped, even to a client that accepts gzip.
- A suffix range on an empty object answers 206 with `Content-Range: bytes 0-0/0`.

### Buckets, IAM and listings

- Bucket IAM policies merge bindings of one role, sort and de-duplicate their members, and drop empty bindings. An etag with non-zero trailing bits answers 412 `conditionNotMet` instead of 400.
- Lifecycle drops unknown condition fields and uses Cloud Storage's messages. Two Autoclass refusals also use Cloud Storage's messages.
- When `uniformBucketLevelAccess` and its `bucketPolicyOnly` alias disagree, the one that changes the stored setting wins.
- Object list page tokens hold only a position, so a token can continue a listing under another prefix, delimiter or versions flag. A `matchGlob` ending in `\` lists nothing instead of failing.

### XML API

- On GET and HEAD:
  - `response-content-type` is trimmed;
  - a non-ASCII `response-content-disposition` passes through;
  - `response-cache-control`, `response-expires` and unknown `response-*` parameters are ignored;
  - an empty override answers 400 `InvalidArgument`.
- Signed URLs still sign every query parameter.

## Compatibility and migration

The catalog schema is unchanged at 53, so a data directory moves between 0.20.1 and 0.21.0 in either direction without a migration. Apart from the changes listed under [What may need attention](#what-may-need-attention), each change accepts a request that 0.20.1 refused, or brings an answer closer to Cloud Storage.

A `gcs-mimic sync` command and the server it manages must still be the same release, so upgrade both together. The Go package accepts a binary of the same minor release, so upgrade `go/fakestorage` to 0.21.0 together with the binary.

## Dependencies and project

- No Rust dependency, Rust toolchain, container base or build tool changes. The package version and the Go package's `moduleVersion` move to `0.21.0`, and the recipes pin `0.21.0`.
- The [differential reference](../../../compatibility/differential/reference/gcs.json) gains 24 Cloud Storage recordings, and every one of its 99 cases replays without a difference. The [gap probe evidence](../evidence/provider-differential-gap-probes.md) records the run, its cost controls and the outcome for each gap.
- The Go SDK test `TestGRPCUpdateCopy` now expects the recorded public access prevention reset.

## Known limitations

- The released-data fixtures for 0.21.0 are added after publication, as for earlier releases.
- Some behaviors share code with recorded ones but were not recorded themselves; the gap entries name them. They include the 304 on rewrite, move and resumable finalize, and XML continuation tokens.
- The limitations listed for [0.20.0](0.20.0.md#known-limitations) still apply, and these changes do not close the [1.0.0 gate](../release-policy.md#the-100-gate).
