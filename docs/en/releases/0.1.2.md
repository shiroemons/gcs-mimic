# gcs-mimic 0.1.2

0.1.2 adds native macOS archives for Apple Silicon (`aarch64-apple-darwin`) and
Intel (`x86_64-apple-darwin`) next to the four Linux archives, and publishes
`ghcr.io/shiroemons/gcs-mimic:0.1.2` for `linux/amd64` and `linux/arm64`.
Application behavior is unchanged from 0.1.1; the
[0.1.0 release notes](https://github.com/shiroemons/gcs-mimic/blob/v0.1.0/docs/en/releases/0.1.0.md)
describe the included workflows, compatibility and known limitations.

## Changes

- macOS archives return to the release matrix. Their native test suites now
  pass on GitHub runners: the TLS test fixtures no longer produce a CA with a
  duplicate `basicConstraints` extension under OpenSSL 1.1.1, and timing-based
  upload deadline tests keep enough margin on slower runners. Test-only changes.
- Windows archives are still not published. Several Windows catalog,
  file-handle and synchronization tests fail on GitHub runners; use the
  container image on Windows hosts.
- Manual dispatch of the release workflow now runs the publish job as a dry
  run up to the Release asset list.

## Compatibility and migration

No migration is required. The data-directory schema remains
`PRAGMA user_version = 21`, shared by 0.1.0, 0.1.1 and 0.1.2. macOS archives are
unsigned and not notarized; macOS recovery limits in the 0.1.0 notes apply.

## Verification

The [release workflow](https://github.com/shiroemons/gcs-mimic/blob/v0.1.2/.github/workflows/binaries.yaml)
creates this Release only after `validate`, Foundation and all six native
macOS and Linux build/test jobs succeed at the tag's SHA. The
[container workflow](https://github.com/shiroemons/gcs-mimic/blob/v0.1.2/.github/workflows/ghcr.yaml)
then builds both Linux architectures natively, verifies their SBOM and
provenance, publishes the multi-architecture tag and checks anonymous pulls.
