# gcs-mimic 0.10.0

0.10.0 makes Rails Active Storage 8.1.4.1 direct uploads work by enforcing `x-goog-content-length-range` on XML object PUT, adds conditional XML reads, guards the management routes against browsers and unexpected hosts, and makes directory synchronization count automatic deletions across split scans and restarts. Most of the remaining changes harden recovery, cleanup, batch admission and gRPC validation. Several changes alter responses or startup requirements that 0.9.0 documented; read [Compatibility and migration](#compatibility-and-migration) before upgrading.

It publishes `ghcr.io/shiroemons/gcs-mimic:0.10.0` for `linux/amd64` and `linux/arm64`, mirrors the same digest to Docker Hub as `shiroemons/gcs-mimic:0.10.0`, and publishes native archives for all eight macOS, Windows and Linux targets. The [feature matrix](../feature-matrix.md) lists the exact supported subsets. Rows marked `PARTIAL` keep their listed missing cases.

## Changes

### XML API

- Object PUT enforces `x-goog-content-length-range: MIN,MAX` as an inclusive byte range. A body outside it answers 400 `EntityTooLarge` or `EntityTooSmall` and publishes nothing; a malformed value answers 400 `ContentLengthRangeInHeaderIsInvalid`. Copies ignore the header. 0.9.0 rejected the header with 400 `InvalidArgument`, which broke Rails 8.1.4.1 direct uploads. The codes and messages follow a Cloud Storage recording from 2026-11-04. See [XML upload size ranges](../slices/xml-content-length-range.md).
- Object GET and HEAD evaluate `If-Match`, `If-None-Match`, `If-Modified-Since` and `If-Unmodified-Since` against the authorized generation and answer 304 or 412; they used to be rejected as unsupported. A malformed entity tag answers 400. `If-Range` remains unsupported. See [XML read validators](../slices/xml-read-validators.md).
- PUT Bucket without a location (or with an empty body) uses the configured `default_location` instead of `US`. See [XML bucket operations](../slices/xml-bucket-operations.md).
- Multipart list uploads, list parts and abort accept requests without `Content-Length` or `Transfer-Encoding`, as live Cloud Storage does; initiation, part upload, complete and copy still answer 411 `MissingContentLength`. `Content-Length: 00` counts as an empty body. See the [framing observations](../evidence/xml-framing-provider-observations.md).

### JSON API and HTTP

- An unknown route answers a JSON `404 notFound` error envelope instead of `{"error":"route not implemented"}`. See [HTTP adapter boundaries](../slices/http-adapter-boundaries.md).
- Batch requests admit two envelopes per server; further envelopes wait up to the request deadline and then answer 503. Parser panics, closed admission and failed inner responses answer 503 `backendError` instead of 400. See [HTTP batch](../slices/http-batch.md).
- `matchGlob` listings examine at most 4096 non-matching names per page, so a page may be empty and still carry `nextPageToken`. See [glob listing](../slices/sdk-list-glob.md).
- Each project keeps the newest 128 deleted HMAC keys; older deleted keys answer 404. See [project HMAC keys](../slices/project-hmac-keys.md).
- Error locations name the rejected boolean query parameter, percent-encoded advisory parameters such as `prettyPrint` are decoded consistently, invalid page tokens are no longer echoed, and custom times before 1970 render correctly.

### gRPC

- Reopening a BidiRead `read_handle` checks current authorization; a deleted or replaced generation of a nonversioned object answers `NOT_FOUND` instead of serving the earlier snapshot. A failing stream reports every pending range.
- Routing metadata is validated on every v2 RPC: conflicting values answer `INVALID_ARGUMENT`, and redirect or other semantic keys and `x-goog-user-project` answer `UNIMPLEMENTED`.
- Object names use the same validator as JSON and XML, so dot-only names and the ACME challenge prefix are rejected. Signed hexadecimal MD5 pairs in v1 are rejected.
- A second stream finalizing the same `upload_id` answers `FAILED_PRECONDITION`. `UpdateObject` rejects `metadata` combined with `metadata.KEY` in the mask. Bucket validation errors name protobuf fields.

### Administration, reset and reseed

- `/_internal` management and sync routes reject browser requests (an `Origin` header or `Sec-Fetch-Site` other than `none`) with 403 and other DNS hosts that are not configured API, public or virtual-host names with 421; IP literals, single-label names and reserved local suffixes are allowed. The new `admin_allowed_hosts` setting (`--admin-allowed-hosts`, `GCS_MIMIC_ADMIN_ALLOWED_HOSTS`) allows up to 32 more names. See [HTTP adapter boundaries](../slices/http-adapter-boundaries.md).
- In strict mode only `admin_principal` may administer, and startup fails when strict administration is enabled without it or names an unknown identity. 0.9.0 allowed any principal with `storage.buckets.update` on `seed_project`. See [runtime admin endpoints](../slices/runtime-admin-endpoints.md).
- Reset and reseed wait up to one second (bounded by `catalog_wait_timeout_ms` and the request deadline) for in-flight catalog work instead of answering 503 at once; on expiry they answer 503 with `Retry-After: 1` and change nothing. See [local instance reset](../slices/local-instance-reset.md) and [atomic reseed](../slices/atomic-seed-reseed.md).

### Directory synchronization

- Automatic deletions count cumulatively toward the approval guard (100 objects or 50%) across split scans and restarts, so splitting a deletion no longer bypasses it. The history resets on approval, on a new baseline, or on a complete scan with no candidates. It is stored in catalog schema 50.
- Native notifications settle after one second of quiet (at most ten seconds). `sync wait` answers 409 `SourceChanging` when the source keeps changing at its deadline. `sync rescan` defaults to a 30-second client timeout.
- Findings and deletions are paged in keyset pages of at most 256 entries or 256 KiB; deletion cursors must be fixed-length lowercase hexadecimal. Storage failures answer 503 `disk_full` or `io_failure` instead of a busy reply. The status writeback summary no longer contains the always-null `journal_sequence` and `journal_epoch`.
- `.gcs-mimic-sync.json.staging` is reserved at every depth; objects with that name stay stored but are not represented in the tree. Linux watches at most 1022 directories. macOS ownership and extended-attribute changes revalidate access, Linux falls back to exact names when the casefold ioctl is unavailable, and installed bytes are verified before they are recorded as durable.
- The sync thread starts before readiness is announced. The sync CLI reports the HTTP status of a non-JSON response without echoing its body.
- See [directory synchronization](../slices/directory-synchronization.md), [continuous observation](../slices/continuous-directory-observation.md) and the [sync CLI](../slices/sync-cli.md).

### Uploads, replay and import

- Upload replay fingerprints use a canonical versioned encoding that distinguishes metadata merge and replace modes. See [upload replay encoding](upload-replay-encoding.md).
- Replays whose source bucket was deleted or recreated answer 412.
- Trusted imports require MD5 and CRC32C and the replace mode, checked before staging. Resume bindings are verified before any catalog change, and missing lock files are restored.

### Authentication and TLS

- Static tokens shaped like a JWT (three dot-separated segments) and aliases that become ambiguous once email domains are case-folded are rejected when the identity registry loads. IAM and ACL email matching folds only the domain's case.
- JWT verification runs on the bounded blocking pool for every transport.
- The signing helper rejects V2 and V4 signing parameter names in `--query` regardless of case. See [signed URLs](../signed-urls.md).
- TLS startup errors name the certificate, key or identity input that failed.

### Configuration and server

- `FAKE_GCS_*` members in a JSON configuration are ignored without warnings. Advertised IPv6 origins drop zone and flow identifiers.
- The listener retries transient accept failures with backoff and logs `accept_failed` and `accept_recovered` instead of stopping.

### Storage, durability and recovery

- Blobs are published without replacing existing files, failed publications are discarded through the reclamation journal, each maintenance sweep runs even when another fails, and resumable and multipart cleanup complete after cancellation.
- Unknown persisted enum values (ACL roles, storage classes, synchronization reasons) are reported as catalog corruption with restore guidance instead of being accepted.

### Dependencies and project

- The Rails Active Storage suite runs on 8.1.4.1, which needs this release. The [Rails guide](../rails-active-storage.md)'s CORS rule now lists `x-goog-content-length-range`.
- The Rust builder image digest, crc32c 0.6.9, BuildKit v0.34.2 and the Node.js `google-auth-library` 11.3.3 are refreshed; the Rust toolchain stays 1.99.1.
- Daily CI regenerates the gRPC code with a digest-pinned `protoc` and detects newer compiler releases (`DESIGN-096` is now `PARTIAL`).
- `cargo xtask differential merge --add-new` appends new cases from a partial recording.
- Releases 0.1.0 through 0.7.0 were withdrawn; see [withdrawn releases](../release-policy.md#withdrawn-releases).

## Compatibility and migration

0.10.0 raises the catalog schema from 49 (0.9.0) to 50, which stores the cumulative automatic-deletion history for directory synchronization. The first start migrates an existing data directory automatically. The migration is one-way: back up the data directory before upgrading, and do not open it with 0.9.0 afterwards. Data directories written by 0.8.0 also upgrade; those of withdrawn releases are not supported.

### Upgrade checklist

- **Back up and migrate.** The catalog moves to schema 50 on first start and cannot be reopened by 0.9.0.
- **Strict administration needs `admin_principal`.** With strict authentication and `admin_enabled`, set `--admin-principal` to the registered identity that administers the instance; project IAM grants no longer authorize management routes.
- **Management hosts and browsers.** Management and sync requests from browsers answer 403. IP literals, single-label names and reserved local suffixes keep working. If you reach them through another DNS name that is not the advertised API or public host, such as the Kubernetes names `gcs-mimic.my-namespace` or `gcs-mimic.my-namespace.svc`, add it to `admin_allowed_hosts`.
- **Identity registry.** Replace JWT-shaped static tokens and aliases that differ only in the email domain's case; the registry now refuses to load them.
- **`x-goog-content-length-range` is enforced.** XML PUTs that send the header must send a body inside the range.

### Behavior changes in detail

- Unknown routes answer the JSON `notFound` envelope; clients that matched the old body must match the status or the envelope.
- Batch internal failures answer 503 instead of 400, and excess concurrent batch envelopes wait and may answer 503.
- Retained upload replays recorded by an older binary may answer 400 until their ten-minute window expires.
- gRPC: reopening a read handle to a removed generation answers `NOT_FOUND`; dot-only and ACME-prefixed object names, conflicting routing metadata and `x-goog-user-project` are rejected; several error messages changed.
- Directory synchronization: deletions count cumulatively toward the approval guard; `sync wait` can answer 409; the deletion cursor format is stricter; the status output drops `journal_sequence` and `journal_epoch`.
- Reset and reseed wait briefly for in-flight work instead of failing at once.
- Glob listings can return empty pages with a page token, and deleted HMAC keys beyond the newest 128 per project answer 404.

## Known limitations

- `If-Range` on XML reads remains unsupported. `EXT-XML-022` stays `PARTIAL` for its other advanced inputs.
- Automatic detection of upstream API and Discovery schema changes is not implemented; `DESIGN-096` covers only pinned protobuf generation and compiler freshness.
- The examples under `examples/` are not run by CI or covered by daily dependency update detection.
- The limitations listed for [0.9.0](0.9.0.md#known-limitations) that these changes do not address still apply, and these additions do not close the [1.0.0 gate](../release-policy.md#the-100-gate).
