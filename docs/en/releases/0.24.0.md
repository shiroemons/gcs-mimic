# gcs-mimic 0.24.0

0.24.0 adds helpers for tests that manage their own buckets and fixtures: a management route that purges one bucket with everything in it, a reset that returns an instance to its startup buckets and seed, seed defaults for runtime fixtures, bucket names as the `buckets` setting, `gcs-mimic buckets new` to write a buckets document, and the Go `gcsmimic` package built on them. Existing commands, options, environment variables and configuration values keep their meaning; the one value whose reading changes is listed under [What may need attention](#what-may-need-attention).

It publishes `ghcr.io/shiroemons/gcs-mimic:0.24.0` for `linux/amd64` and `linux/arm64`, mirrors the same digest to Docker Hub as `shiroemons/gcs-mimic:0.24.0`, and publishes native archives for all eight macOS, Windows and Linux targets. The [feature matrix](../feature-matrix.md) lists the exact supported subsets.

## What may need attention

- **A `buckets` value that is not a document is read as bucket names.** A `GCS_MIMIC_BUCKETS`, `--buckets` or config file string that does not start with `{` after leading whitespace is now comma-separated bucket names, such as `GCS_MIMIC_BUCKETS=uploads,exports`, each created in `seed_project` with default settings. 0.23.0 refused such a value at startup. An invalid or repeated name fails startup for the supplying key, and a config file object member is still a document.
- **Go packages stop their child gracefully on Windows.** `fakestorage` and the new `gcsmimic` start the child in its own process group and stop it with CTRL_BREAK, because Windows cannot send an interrupt to another process. An interrupt that cannot be delivered now kills the child at once instead of after ten seconds.

## Changes

### Local management

- `DELETE /_internal/buckets/{bucket}` removes a bucket with every live, noncurrent and soft-deleted generation, its upload, multipart, appendable and rewrite sessions, its policy, ACLs, notification configurations and queued events, past holds and retention, and answers `{"objects","cleanupPending"}`. It takes no instance-wide gate: it claims only the writers of that bucket's sessions and answers 503 with `Retry-After: 1` and no changes while a request writes one, so other buckets neither wait nor hold it back. `DELETE /storage/v1/b/{bucket}` is unchanged. See [bucket purge](../slices/bucket-purge.md).
- `POST /_internal/reset` accepts `"state": "startup"`, which clears the catalog, applies the startup buckets document and publishes the `seed_dir` tree in one transaction, so a test returns to its fixtures without restarting and no reader sees the startup buckets missing. `"empty"` stays the default. With management enabled the server keeps the buckets document it read at startup, so a later edit of `buckets_file` does not change what the reset restores. See [local instance reset](../slices/local-instance-reset.md#reset-to-the-startup-state).
- A runtime fixture in `POST /_internal/objects` may set `"defaults": "seed"`, so the object is published as a startup seed would publish it: owned by the project owners, under the bucket's default event-based hold, and with a missing `contentType` taken from the object name's extension before the media part's type. An explicit generation or time is refused instead of replaced.
- Reseed and reset failures name the operation that made no changes.

### Configuration and CLI

- The `buckets` setting accepts comma-separated bucket names, as described under [What may need attention](#what-may-need-attention).
- `gcs-mimic buckets new --name NAME [SETTING]...` writes a buckets document as JSON for `buckets_file`, one single-quoted `GCS_MIMIC_BUCKETS` line, or a Compose `environment:` block. Settings after a `--name` belong to that bucket. Without `--name` on a terminal it asks for each bucket's name, its settings and the format, offering the storage classes, locations and bucket roles the server accepts. A name or label startup would refuse is explained and asked again, and every document passes the startup parser before it is written; `--output` refuses an existing file. In the image, which has no shell, run `docker run --rm -it ghcr.io/shiroemons/gcs-mimic:0.24.0 buckets new`. See [writing a document with `buckets new`](../slices/bucket-initialization.md#writing-a-document-with-buckets-new).

### Go

- The new `gcsmimic` package is the module's native package for tests. `Start` runs gcs-mimic over plain HTTP on loopback with a memory catalog, permissive authentication and local management, and stops it at test cleanup; `New` does the same for `TestMain`. `TempBucket` creates a uniquely named bucket and purges it at cleanup, `Seed` writes in-code objects and directories or `fs.FS` trees laid out as a startup seed, whose files take the seed's content types and owners, and `Reset` returns to the startup state. See [Go packages](../../../go/README.md).
- `fakestorage` keeps its public API. It now shares process start, ready checks and the stop sequence with `gcsmimic`, and its version error names the package that refused the binary.

## Compatibility and migration

The catalog schema is unchanged at 53, so a data directory moves between 0.23.0 and 0.24.0 in either direction without a migration. Apart from the `buckets` value under [What may need attention](#what-may-need-attention), each change adds a route, a request member or a command, or accepts a request that 0.23.0 refused.

A `gcs-mimic sync` command and the server it manages must still be the same release, so upgrade both together. The Go packages accept a binary of the same minor release, so upgrade the Go module to 0.24.0 together with the binary.

## Dependencies and project

- `inquire` 0.9.5 is a new direct dependency for the `buckets new` questions, built with only its crossterm backend. It adds 21 locked packages, all MIT or MIT OR Apache-2.0, and grew the stripped release binary on aarch64-apple-darwin by 373,280 bytes (2.0%) when it was added. Release notices supply the license text that the published `inquire` and `winapi` windows-gnu crates omit. No Rust toolchain or container base changes. The package version and the Go module's `ModuleVersion`, now in `go/internal/mimicproc`, move to `0.24.0`, and the recipes pin `0.24.0`.
- The development-only Ruby suites and scorecard move to Bundler 4.1.0, which also locks the `ruby` variants of nokogiri and sqlite3 in the Active Storage suite.
- The Temurin and Maven checksums of the development-only Java suite live beside their version pins, and the dependency check compares them with the publishers' checksums.
- The released-data fixture for 0.23.0 joins the upgrade test, so data directories from 0.8.0 through 0.23.0 are opened by the new build.
- The [eighth 2026-11-15 scorecard comparison](../../../sdk-scorecard/results/2026-11-15-8/summary.md) runs 2,324 cases on the 0.23.0 source: gcs-mimic scores 100 with Core 100 and passes every case for all nine SDKs, floci-gcp 74.2, fake-gcs-server 39.2 and gcp-storage-emulator 35.7.
- The [feature ledger](../../../compatibility/features.json) records the purge, the startup reset, the seed defaults, the bucket name shorthand, the generator and the Go helpers on DESIGN-062, DESIGN-068 and DESIGN-082, which stay `PARTIAL`.

## Known limitations

- The released-data fixture for 0.24.0 is added after publication, as for earlier releases.
- The `buckets new` questions have not been checked on a Windows console, including Windows on ARM64 and the legacy console host; the flags work wherever the questions do not.
- The purge route holds bucket names to the native rules, so a bucket that only the `fake-gcs-server` profile admits must be deleted through the JSON API.
- `fakestorage`'s `NoListener` mode needs a Unix socket and refuses to start on Windows, where gcs-mimic serves none.
- The limitations listed for [0.23.0](0.23.0.md#known-limitations) still apply, and these changes do not close the [1.0.0 gate](../release-policy.md#the-100-gate).
