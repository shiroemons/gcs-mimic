# gcs-mimic 0.19.0

0.19.0 changes the default `scheme` from `https` to the new value `auto`, which serves HTTP and HTTPS on the same port. This is the change the [0.18.0 release notes](0.18.0.md#upgrade-checklist) announced for the next minor release, and the last scheme decision of the [public contract review](../public-contract-review.md) before the 1.0.0 freeze. HTTPS clients of the old default keep working unchanged; plain HTTP clients, such as SDKs given `STORAGE_EMULATOR_HOST`, now connect without a setting. Read [Breaking changes](#breaking-changes) if you relied on plain HTTP being refused, pass TLS files without `scheme`, or read the ready event.

It publishes `ghcr.io/shiroemons/gcs-mimic:0.19.0` for `linux/amd64` and `linux/arm64`, mirrors the same digest to Docker Hub as `shiroemons/gcs-mimic:0.19.0`, and publishes native archives for all eight macOS, Windows and Linux targets. The [feature matrix](../feature-matrix.md) lists the exact supported subsets. Rows marked `PARTIAL` keep their listed missing cases.

## Breaking changes

### The `scheme` default serves HTTP and HTTPS on one port

An `auto` listener reads the first byte of each connection without consuming it: a TLS handshake record selects TLS, and anything else plain HTTP. The same port therefore answers `https://localhost:4443` with the development certificate, as before, and `http://localhost:4443` as well.

| If you | 0.18.0 | 0.19.0 | What to edit |
| --- | --- | --- | --- |
| Rely on plain HTTP being refused | Default refused plain HTTP | Default serves it | Set `scheme=https` |
| Pass `tls_cert` and `tls_key` without `scheme` | HTTPS only | HTTPS and plain HTTP, with your certificate | Set `scheme=https` to keep HTTPS only |
| Read `scheme` in the ready event | `https` | `auto` | Accept `auto`; `listeners[0].scheme` becomes `http` |
| Use the ready event's `api_base_url`, or links built without an explicit `api_base_url` and without a usable request authority | `https://…` | `http://…` | Set `api_base_url` to keep HTTPS links |
| Set `scheme=http` only because of the old default | Needed for HTTP clients | Optional | Remove it, or keep it to refuse HTTPS as before |
| Use `unix_socket` | Required `scheme=http` | `scheme` can be left out | Optionally remove `scheme=http` |

Configurations that set `--scheme http`, `--scheme https` or `--scheme both` behave as before.

## New behavior

- `--scheme`, `GCS_MIMIC_SCHEME` and JSON `"scheme"` accept `auto`, `http`, `https` and `both`. `auto` is the default under every `auth_mode` and `compat_profile`.
- `tls_cert` and `tls_key` choose the certificate only; `scheme=https` is what makes a listener HTTPS-only. Without them, `auto` uses the bundled development certificate, as `https` does.
- Without an explicit `api_base_url`, JSON links and the resumable-upload session URL use the scheme and authority of the connection that asked: `https://` over TLS, `http://` in plain HTTP. An explicit `api_base_url` is returned unchanged over both.
- Where no connection supplies a scheme, `auto` uses `http`: the fallback API base, the ready event's `listeners[].scheme` and `gcs-mimic healthcheck` without `--url`, which therefore needs no CA.
- A connection waits for its first byte for at most `header_read_timeout_ms` from accept, the limit a silent plain HTTP client has, and the TLS handshake limit `tls_handshake_timeout_ms` also counts from accept, so detection extends neither. A connection closed before its first byte, such as a TCP probe, emits no diagnostic.
- A Unix socket serves plain HTTP under `auto`; `https`, `both` or TLS settings beside `unix_socket` stop startup.
- The trusted listener stays plain HTTP, the gRPC listener is unchanged, and `scheme=both` keeps HTTPS on `listen` and HTTP on `listen_http`.
- fake-gcs-server's `--public-host` without `--scheme` still translates to an `https://` public base, as fake-gcs-server builds it.
- No response redirects between the protocols or sends `Strict-Transport-Security`, so a browser never pins the port to HTTPS.

The [design](../slices/single-port-scheme.md) records the owner decisions and the acceptance cases.

## Compatibility and migration

The catalog schema is unchanged at 53, so a data directory moves between 0.18.0 and 0.19.0 in either direction without a migration.

### Upgrade checklist

- **Clients that must not use plain HTTP.** Set `scheme=https`, including where you pass `tls_cert` and `tls_key`.
- **Ready-event readers.** Accept `scheme: "auto"`, `listeners[0].scheme: "http"` and an `http://` `api_base_url`.
- **Fixed HTTPS links.** Set `api_base_url` if a client needs `https://` links from requests that name no usable authority.
- **Recipes.** The [strict local recipe](../../../examples/strict-local/README.md) and the [full application example](../../../examples/full-stack/README.md) pin `0.19.0` and no longer set `GCS_MIMIC_SCHEME: http`. Their listener entries still report `http`.

## Dependencies and project

- BuildKit, which builds the release images and their SBOM and provenance attestations, moves from v0.34.2 to v0.35.0. No Rust dependency, Rust toolchain or container base changes. The package version moves to `0.19.0`.

## Known limitations

- DESIGN-102 stays `PARTIAL`. A V4 signed URL over both protocols on one port, concurrent HTTP and HTTPS clients, a full `max_connections` of silent connections, and the pinned SDK suites, a browser and the image `HEALTHCHECK` against a default server without a scheme setting have not been verified as cases of this change. The [verification record](../evidence/single-port-scheme.md) lists what has.
- Detection reads one byte, so a client that sends an SSLv2-format hello is served as plain HTTP and fails there; rustls supports neither that format nor those protocol versions.
- The bundled development key is public, so HTTPS with it authenticates nothing, as before.
- The released-data fixtures for 0.19.0 are added after publication, as for earlier releases.
- The limitations listed for [0.18.0](0.18.0.md#known-limitations) still apply, and these changes do not close the [1.0.0 gate](../release-policy.md#the-100-gate).
