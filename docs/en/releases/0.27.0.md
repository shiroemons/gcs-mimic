# gcs-mimic 0.27.0

0.27.0 serves gRPC over TLS on the dedicated gRPC listener and answers Storage v2 routing metadata, conditions, field masks, write streams and upload IDs as Cloud Storage answered them in differential recordings up to 2026-11-18, replayed offline; the reference grows by 18 cases. Existing commands, options, environment variables and configuration values keep their meaning, and the JSON and XML answers are unchanged; the Storage v2 answers that change are listed under [What may need attention](#what-may-need-attention).

It publishes `ghcr.io/shiroemons/gcs-mimic:0.27.0` for `linux/amd64` and `linux/arm64`, mirrors the same digest to Docker Hub as `shiroemons/gcs-mimic:0.27.0`, and publishes native archives for all eight macOS, Windows and Linux targets. The [feature matrix](../feature-matrix.md) lists the exact supported subsets.

## What may need attention

- **A Storage v2 call needs its routing metadata.** A call without `x-goog-request-params`, or with only empty values, answers `INVALID_ARGUMENT` with ErrorInfo reason `GRPC_INVALID_X_GOOG_REQUEST_PARAMS`, where 0.26.0 served it. Metadata that routes no bucket for a call that names one, such as a WriteObject carrying `appendable=false` alone, is refused as well. The official SDK clients send the metadata; a hand-written gRPC client has to add it. In the other direction, an unknown key, a `routing_token` and a key the RPC does not route are accepted, where 0.26.0 answered `UNIMPLEMENTED`. See the [Storage v2 foundation](../slices/grpc-v2-foundation.md).
- **The gRPC listener detects TLS by default.** With `grpc_listen` set, the new `grpc_scheme` defaults to `auto`: the first byte of a connection selects TLS or plaintext h2c, so existing plaintext clients keep working. The server no longer sends its HTTP/2 SETTINGS to a client that stays silent, and closes such a connection after one `header_read_timeout_ms` where 0.26.0 took two. `grpc_scheme=h2c` keeps the 0.26.0 behavior.
- **Storage v2 requests that 0.26.0 served are refused.**
  - A resumable stream that closes with bytes past its last whole 256 KiB granule fails and drops those bytes; 0.26.0 persisted every message.
  - A finishing message of the wrong size ends the session, and every later call on it answers `FAILED_PRECONDITION` with reason `GRPC_UPLOAD_ALREADY_TERMINATED`; 0.26.0 left the session open.
  - An invalid read mask on GetObject, ReadObject and ListObjects is refused before authorization and lookup, so it is reported for a missing object and an empty listing too.
  - UpdateBucket compares a retention duration by its value: one second less a nanosecond answers `INVALID_ARGUMENT`, where 0.26.0 stored 1, and 3600 seconds less a nanosecond is stored as 3599.
- **Storage v2 requests that 0.26.0 refused are served.**
  - A negative generation or metageneration condition is evaluated on every object RPC and on UpdateBucket. A metageneration match of 0 and a match beside a not-match are evaluated on UpdateBucket, UpdateObject, RewriteObject and RestoreObject; MoveObject evaluates the match of 0 and still refuses the pair. A condition that fails answers `FAILED_PRECONDITION`, where 0.26.0 answered `INVALID_ARGUMENT` for all of these.
  - CreateBucket rounds a retention duration with nanoseconds down to whole seconds and ignores output-only fields such as `bucket_id`, `metageneration`, `create_time` and `owner`; 0.26.0 answered both with `UNIMPLEMENTED`.
  - An update mask accepts a path that no update changes, such as `name`, `etag` and the output-only fields. UpdateObject advances the metageneration for it and UpdateBucket does not.
  - UpdateObject accepts the `*` mask as a replacement of the editable metadata, and GetObject reads a soft-deleted generation.
  - CancelResumableWrite on an upload that is already cancelled succeeds, where 0.26.0 answered `NOT_FOUND`.
- **Storage v2 refusals that change status.**
  - An upload ID whose session is missing, expired or in another bucket, and an ID that cannot be read, answer `INTERNAL` on WriteObject, QueryWriteStatus and CancelResumableWrite, as Cloud Storage answered; text that is no upload ID answers `INVALID_ARGUMENT`. 0.26.0 answered `NOT_FOUND` for all of them.
  - On a cancelled upload, a write answers `INVALID_ARGUMENT` and QueryWriteStatus answers `FAILED_PRECONDITION` with reason `GRPC_UPLOAD_ALREADY_CANCELLED`; CancelResumableWrite on a completed upload carries reason `GRPC_UPLOAD_ALREADY_COMPLETED`. 0.26.0 answered `NOT_FOUND`.
  - A first `write_offset` past the persisted size, a size that cannot make `object_size` and a finishing message whose bytes miss the stream's `object_checksums` are refused with Cloud Storage's status, reason and wording instead of the earlier local ones.
  - A mask path that names no field answers `INVALID_ARGUMENT` on UpdateBucket, UpdateObject and the object read masks, as do the UpdateObject paths `storage_class` and `kms_key` and a fractional soft delete duration on CreateBucket and UpdateBucket; 0.26.0 answered `UNIMPLEMENTED`. GetObject with a `restore_token` answers `INTERNAL`.
  - A not-match condition that alone fails is worded as a resource that has not been modified.
  - A strict-mode caller without `storage.objects.create` receives `PERMISSION_DENIED` for an appendable BidiWriteObject before its opening message is examined, and a refused opening message leaves no object behind.
- **BidiReadObject with the read mask `*` returns the ACL and owner**, where 0.26.0 returned the default fields.
- **`scheme=http` with TLS files starts when the gRPC listener uses them.** `tls_cert`, `tls_key` and `tls_handshake_timeout_ms` beside `scheme=http` stay a startup error only when no listener serves TLS: without `grpc_listen`, or with `grpc_scheme=h2c`.

## Changes

### gRPC over TLS

- `grpc_scheme` (`--grpc-scheme`, `GCS_MIMIC_GRPC_SCHEME`) takes `auto`, `h2c` or `tls` and needs `grpc_listen`. `auto` serves TLS 1.2, TLS 1.3 and plaintext h2c on the one gRPC port; `h2c` refuses TLS clients and `tls` refuses plaintext ones. See [gRPC over TLS](../slices/grpc-tls.md).
- The gRPC listener uses the HTTPS identity: `tls_cert` and `tls_key`, or the built-in development certificate, even with `scheme=http`. It offers ALPN `h2` only, and `tls_handshake_timeout_ms` bounds its handshakes as it bounds HTTPS ones. The HTTP listeners keep offering `http/1.1` only, so a gRPC client still dials the gRPC port.
- With a gRPC listener the ready event carries `grpc_scheme`, and the listener's `listeners[]` entry reports `h2c` while plaintext is accepted and `h2` for `tls`. The ready event of a server without a gRPC listener is unchanged.
- A TLS identity the gRPC listener would use and cannot load stops startup before the ready event with a diagnostic naming `tls_cert` or `tls_key`. A key that does not match its certificate has its own repair message, and `grpc_listen` beside a Unix socket reports the unused settings without reading the TLS files.
- The `tls_handshake_failed` log event carries a `cause`, on HTTPS too, and the gRPC connection events name what the configured scheme accepts.

### Storage v2 routing and upload IDs

- Each call reads the value of every key some RPC routes once and refuses a malformed value or a repeated key, then compares only the keys its own RPC routes.
- QueryWriteStatus and CancelResumableWrite check the upload ID's form first; for a readable ID the routed bucket is compared with the session's bucket after authentication and authorization.

### Storage v2 buckets and objects

- Bucket and object conditions, update masks and their refusals follow the recordings of 2026-11-18. See the [bucket contract](../slices/grpc-v2-buckets.md) and [update and copy](../slices/grpc-v2-update-copy.md).
- Object read masks accept members of a singular message such as `owner.entity`, timestamp parts, `contexts.custom` and, on ReadObject, `object_checksums.crc32c`.
- GetObject refuses the soft-deleted lookup on a bucket without a soft delete policy as RestoreObject does.
- ComposeObject accepts a destination naming the sources' storage class, and ComposeObject and RewriteObject ignore service-set destination fields; RewriteObject still refuses a destination that carries a generation.

### Storage v2 write streams

- WriteObject and BidiWriteObject answer at `finish_write` and read nothing after it, ignore a repeated `write_object_spec` or `upload_id`, and accept `object_checksums` on any message. See [object I/O](../slices/grpc-v2-object-io.md).
- An upload persists whole 256 KiB granules until `finish_write`. A write's answer carries `persisted_data_checksums` with the CRC32C of the persisted bytes, and QueryWriteStatus reports their MD5 too; a session staged before 0.26.0 reports none.
- A resumed stream may start at or below the persisted size, and the repeated bytes are skipped. A resumed BidiWriteObject stream that the client closes cleanly always receives a final response.
- A panic in a gRPC stream is reported as `background_task_panicked` with the task name `grpc-stream` and resets only that stream.

### Differential harness

- The reference grows from 147 to 165 cases; the [evidence page](../evidence/provider-differential-gap-probes.md) describes the recordings.

## Compatibility and migration

The catalog stays at schema 57, so 0.26.0 and 0.27.0 open each other's data directories. A data directory from 0.8.0 through 0.25.0 is migrated to schema 57 when 0.27.0 first opens it, as 0.26.0 migrated it.

A `gcs-mimic sync` command and the server it manages must still be the same release, so upgrade both together. The Go packages accept a binary of the same minor release, so upgrade the Go module to 0.27.0 together with the binary.

## Dependencies and project

- The Rust toolchain, `Cargo.lock` and the build image are those of 0.26.0. The Go module requires google.golang.org/api v0.316.0. Development-only pins move to `bytes` 1.12.2 in the Rust SDK suite and scorecard, Java `google-cloud-storage` 2.79.0, PHP `google/cloud-storage` 2.7.0, Ruby 4.0.10 and genproto 20261118. The package version and the Go module's `ModuleVersion` move to `0.27.0`, and the recipes pin `0.27.0`.
- The dependency freshness check honors a recorded exception until its review date and reports it as `DEFERRED`; the release-scoped check never honors one. One exception is recorded: Temurin 27.0.1.1+4 in the Java SDK suite and scorecard, for review by 2026-11-26.
- The Go module, tagged `go/v0.26.0`, is tagged `go/v0.27.0` after publication, once its `SHA256SUMS` records this Release's archives.
- The released-data fixture for 0.26.0 joins the upgrade test, so data directories from 0.8.0 through 0.26.0 are opened by the new build.
- The gRPC and XML adapters no longer reference the JSON adapter: the error type and failure wording they shared with it live in neutral modules, without a change to any answer. The production lint gate denies more idiomatic Rust lints on every release target.
- The [feature ledger](../../../compatibility/features.json) adds DESIGN-104 (gRPC over TLS) as implemented and moves DEP-007 to partial. The [gap ledger](../../../compatibility/gaps.json) opens SPEC-GRPC-CALL-METADATA, SPEC-GRPC-LOCAL-CHOICES and SPEC-GRPC-UNMODELED-SETTINGS for the answers that remain local choices.

## Known limitations

- The released-data fixture for 0.27.0 and the Go module's `SHA256SUMS` for 0.27.0 are added after publication, as for earlier releases. Until `go/v0.27.0` is tagged, a Go module revision between this release and that commit cannot download its binary; set `GCSM_BINARY` there.
- Storage v2 answers that no recording covers stay local choices that the ledger names under SPEC-GRPC-LOCAL-CHOICES: UpdateBucket's `*` update mask and nested bucket read masks answer `UNIMPLEMENTED`, as do a destination `acl` on ComposeObject and RewriteObject and IAM calls on an object resource. CreateBucket still refuses a nonempty `etag` and a locked retention policy.
- The gRPC listener has no mutual TLS, and the HTTP listeners do not serve gRPC.
- The limitations listed for [0.26.0](0.26.0.md#known-limitations) still apply, and these changes do not close the [1.0.0 gate](../release-policy.md#the-100-gate).
