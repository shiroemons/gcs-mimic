# gcs-mimic 0.19.1

0.19.1 corrects the help and the guides where they described something other than what the server does, builds `--help` from one line per setting so that the two cannot drift apart again, and completes the verification of the 0.19.0 default scheme, which serves HTTP and HTTPS on one port. No command, option, environment variable, default, API response or machine-readable output changes, and no setting or data needs attention when upgrading from 0.19.0.

It publishes `ghcr.io/shiroemons/gcs-mimic:0.19.1` for `linux/amd64` and `linux/arm64`, mirrors the same digest to Docker Hub as `shiroemons/gcs-mimic:0.19.1`, and publishes native archives for all eight macOS, Windows and Linux targets. The [feature matrix](../feature-matrix.md) lists the exact supported subsets. Rows marked `PARTIAL` keep their listed missing cases.

## Changes

### Help and guides that disagreed with the code

The [public contract review](../public-contract-review.md#disagreements-between-code-and-documents) listed these; each now states what the code does.

- `--sync-delete-guard` names its threshold and `gcs-mimic sync approve` instead of "deletion ingestion pending".
- `--seed-dir` no longer claims the image sets it; the image sets `default_seed_dir`, which `seed_dir` overrides.
- `--default-location` accepts every region and dual-region, not only `US`, `EU` and `ASIA`.
- `--event-list none` turns off the global rule that the topic settings configure; any value other than `finalize` needs those settings.
- `--memory-max-bytes` is half of the memory left after 32 MiB, from 64 MiB to 1 GiB, and 1 GiB wherever the memory cannot be read, which is every system but Linux. `llms.txt` says the same.
- `gcs-mimic healthcheck` without `--url` retries with the options of a server running as PID 1 when its first probe fails, as in the container image.
- `--trusted-listen` names the headers it refuses, `Origin` and a `Sec-Fetch-Site` other than `none`, instead of "browser requests"; see [Trusted listener and browsers](#trusted-listener-and-browsers).
- The usage line lists every accepted help and version spelling, `sync --help` shows the `deletions` and `findings` forms the main help lists, and `url sign --help` lists `POST` for a resumable upload start with `x-goog-resumable:start`.
- The approval error of `gcs-mimic sync approve` names `--deletion-set`, as its help does.
- The [native binary guide](../native-binary.md) lists the 18 options its table lacked and states that a JSON config file's 64 KiB limit also bounds inline `buckets` and `identities` there. `llms.txt` lists `--lifecycle-execution` and every optional bucket entry field. The [container guide](../container-usage.md) names `GCS_MIMIC_TRUSTED_ALLOWED_HOSTS` among the settings that accept an empty value. The management guides promise request bodies of 64 KiB, as the release policy does.

### One help line per setting

`--help` is built from an exhaustive list with a line for every setting, so a new setting does not compile without its line. Tests require the help, the option table of the native binary guide and the option list of `llms.txt` to name every option once, and `scripts/check-docs.sh` runs them for documentation-only changes too. The words of the help are unchanged; eight lines now start their description in the same column as the others.

### Default scheme verified with real clients

DESIGN-102, HTTP and HTTPS on one port as the default scheme, is now `IMPLEMENTED`. Beyond the 0.19.0 checks:

- A V4 URL signed for the `https://` origin and one signed for the `http://` origin each verify over both protocols on the same port, because V4 signs the Host and never the scheme. `signed_host_port` treats a Host without its port the same way over both. On ports 80 and 443 a client of the other protocol names the port in Host, so there a URL signed for that port's own protocol verifies over the other only with `signed_host_port=lenient`; see [Signed URLs](../slices/single-port-scheme.md#signed-urls).
- Connections that send nothing hold their slots until `header_read_timeout_ms`, and the next client of either protocol is then served; HTTP and HTTPS clients share the port at the same time.
- The pinned Go and Ruby SDK suites pass against servers started without `--scheme` or `--api-base-url`, with HTTP clients and with HTTPS clients trusting the exported development CA. Chromium loads public objects and signed downloads over both protocols on the strict local recipe's port, and the image's own `HEALTHCHECK` passes for a container started with no setting.

### Trusted listener and browsers

Chromium now also runs against the trusted listener from the strict local recipe's Compose network. On loopback it marks every request a page starts, which gets 403. To a plain HTTP service name such as `http://gcs:4444` it sends no `Sec-Fetch-Site`, so a GET navigation or an image a page starts reaches the listener and acts as the trusted principal. The page cannot read the response, the image is blocked by `Cross-Origin-Resource-Policy`, and every write a page tried was refused. Point a browser on the Compose network, such as an end-to-end test runner, at the main listener; the [trusted listener guide](../container-usage.md#keep-private-buckets-private-with-a-trusted-listener) says so. DESIGN-101 stays `PARTIAL` with this recorded in its deviations.

## Compatibility and migration

The catalog schema is unchanged at 53, so a data directory moves between 0.19.0 and 0.19.1 in either direction without a migration. Only human-readable text changes: the help, one `gcs-mimic sync` error message and the guides. None of it is part of the stable contract, which covers names, exit codes and machine-readable output.

## Dependencies and project

- No Rust dependency, Rust toolchain, container base or build tool changes. The package version moves to `0.19.1`, and the recipes pin `0.19.1`.
- `scripts/sdk-go.sh` accepts `GCSM_SDK_SERVER_SCHEME=auto` to run the SDK suites against servers in their default configuration.

## Known limitations

- The SDK, browser and container clients of the default scheme ran on macOS and linux/arm64 only, with Chromium as the only browser; signed URLs on ports 80 and 443 were not exercised.
- The released-data fixtures for 0.19.1 are added after publication, as for earlier releases.
- The limitations listed for [0.19.0](0.19.0.md#known-limitations) still apply, except that DESIGN-102 is now `IMPLEMENTED`, and these changes do not close the [1.0.0 gate](../release-policy.md#the-100-gate).
