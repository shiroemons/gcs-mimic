# gcs-mimic 0.17.0

0.17.0 makes the RAM backend practical for continuous integration and removes a bottleneck in reads that miss the read cache. The RAM backend's default object budget now follows the memory the process may use, from 64 MiB to 1 GiB, and its repeated reads no longer line up on one connection. Disk reads past the read cache are four to eight times as fast at 8 or more connections. If a test relies on the old 64 MiB limit, read [Compatibility and migration](#compatibility-and-migration) before upgrading.

It publishes `ghcr.io/shiroemons/gcs-mimic:0.17.0` for `linux/amd64` and `linux/arm64`, mirrors the same digest to Docker Hub as `shiroemons/gcs-mimic:0.17.0`, and publishes native archives for all eight macOS, Windows and Linux targets. The [feature matrix](../feature-matrix.md) lists the exact supported subsets. Rows marked `PARTIAL` keep their listed missing cases.

## Changes

### RAM backend

- The default of `memory_max_bytes` is half of the available memory less 32 MiB, within 64 MiB to 1 GiB. Available memory is the tightest cgroup limit on the process or the machine's total on Linux. Elsewhere it is unknown, which selects 1 GiB. An explicit setting still wins, and the `ready` event reports the value in use.
- Unused budget costs nothing. Idle process memory stayed at 9.7 MiB with budgets of 64 MiB, 1 GiB and 10 GiB. The [RAM contract](../slices/memory-backend.md) records why the default is half and how far the budget is from process memory.
- Repeated live reads with permissive access are answered from the read cache. An entry shares the object's chunks, takes no file descriptor and leaves with the write that replaces or deletes the object. With 100 KiB objects, RAM downloads rose from about 19,000 requests per second at any connection count to 55,740 at 8 connections and 123,497 at 32.

### Reads past the read cache

- Disk reads that missed the read cache stopped near 8,000 requests per second at any connection count. SQLite no longer keeps process-wide allocation statistics, and read connections keep a statement's plan when a bound value changes.
- With 100 KiB objects, the same reads now reach 36,459 requests per second at 8 connections and about 63,000 at 32 and 128. Reads that hit the cache and uploads are unchanged. The [measurements](../evidence/read-path-performance.md#reads-past-the-read-cache-and-ram-reads) list the conditions and the comparison with fake-gcs-server.

### Documentation

- The README compares [floci-gcp](../evidence/floci-gcp-comparison.md) alongside the other emulators, and the [SDK scorecard](../../../sdk-scorecard/README.md) includes it.

### Dependencies and project

- No dependency is added.
- The Java SDK suite and scorecard move to `exec-maven-plugin` 3.7.0, the Node.js SDK suite to `google-auth-library` 11.3.4 and the Go SDK suite to `google.golang.org/genproto` v0.0.0-20261110000943-09e21b237f2c. None is part of the release binaries or images.
- `.cargo/config.toml` now passes `LIBSQLITE3_FLAGS` to the SQLite build, and the container build copies it. A build started outside the repository root does not read that file. It behaves correctly but keeps the old limit on reads past the cache.

## Compatibility and migration

0.17.0 keeps catalog schema 52. A data directory that 0.16.0 used opens without a migration.

### Upgrade checklist

- **Tests that expect a 503 at 64 MiB.** The default budget is now usually larger. Set `memory_max_bytes` to `67108864`, through `GCS_MIMIC_MEMORY_MAX_BYTES` or `--memory-max-bytes`, to keep the old limit.
- **The `ready` event.** `memory_max_bytes` reports the computed default, also on the disk backend, which ignores it. Do not compare it with a fixed number.

## Known limitations

- The budget does not limit process memory. Deleting every other object and refilling with other sizes left about 1.8 times the budget resident, which is why the default is half of the available memory.
- A 128 MiB container keeps the 64 MiB minimum and can still be OOM-killed by that sequence, as in earlier releases.
- At one connection, reads past the read cache remain slower than fake-gcs-server. RAM reads past the 4,096 cached records and requests with strict authentication still use the catalog connection.
- The limitations listed for [0.16.0](0.16.0.md#known-limitations) still apply, and these changes do not close the [1.0.0 gate](../release-policy.md#the-100-gate).
