# gcs-mimic 0.5.0

0.5.0 extends the [SDK scorecard](../../../sdk-scorecard/README.md) from Go and
Ruby to five official SDKs: gcs-mimic passes 57 of 57 Go probes and 51 of 51
probes each for Ruby, Node.js, PHP and Python. It adds ACL replacement through
bucket and object PATCH and PUT, bounded response replay for media, multipart
and copy invocation tokens, bounded gzip expansion on JSON media downloads and
JSON object metadata HEAD. It publishes `ghcr.io/shiroemons/gcs-mimic:0.5.0`
for `linux/amd64` and `linux/arm64`, mirrors the same digest to Docker Hub as
`shiroemons/gcs-mimic:0.5.0`, and publishes native archives for all eight
macOS, Windows and Linux targets. The [0.4.1 release notes](0.4.1.md) describe
the previous published release; the [feature matrix](../feature-matrix.md)
lists the exact supported subsets.

The first start migrates the data directory to a catalog schema that 0.4.1
cannot open. Read [Compatibility and migration](#compatibility-and-migration)
before upgrading a persistent deployment.

## Changes

### Access control

- Bucket PATCH and PUT accept `acl` and `defaultObjectAcl`, and object PATCH
  and PUT accept `acl`. A supplied array replaces the stored entries, an empty
  array clears them and omission keeps them. Replacement needs both the
  metadata update permission and the resource's `setIamPolicy` permission.
  The ACL and the other supplied metadata commit in one transaction with one
  metageneration increment; invalid entries, missing permissions, failed
  preconditions, uniform bucket-level access and public access prevention roll
  back the whole update. See the [ACL contract](../slices/json-acl.md).

### Objects

- Media and multipart uploads and JSON copy accept an
  `X-Goog-Gcs-Idempotency-Token` with or without generation conditions. A
  matching retry returns the original response, even after a later overwrite,
  deletion or restart, and concurrent identical requests publish one
  generation. A conflicting request with the same token returns 400. Completed
  invocations are kept for ten minutes, at most 4096 entries of up to 64 KiB
  each; a full store rejects new tokens with 503. Current permissions are
  checked on every retry. See the
  [upload replay contract](../slices/sdk-upload-replay.md).
- JSON media downloads of objects stored with `Content-Encoding: gzip` are
  decompressed in bounded buffers unless the client accepts gzip or the object
  has `Cache-Control: no-transform`. Decompressed responses ignore `Range`,
  keep the stored hashes and ETag, and abort on corrupt or oversized data.
- JSON object metadata HEAD selects the same generation and applies the same
  conditions and permissions as GET, without a response body.
- Object move accepts an empty JSON object as its body, as the Node.js SDK
  sends, and still rejects meaningful body fields. Compose accepts a null
  source generation, and object retention accepts a null nested
  `retentionExpirationTime`, as the Python SDK sends.

### Uploads

- Resumable chunks may repeat whole-object MD5 and CRC32C declarations, as the
  PHP SDK sends. The declarations persist with the acknowledged offset and are
  verified against the complete object at finalization; conflicting or new
  declarations, including on retries of a completed upload, return 400 without
  changing the object.
- After initiation, a repeated `X-Upload-Content-Type`, as the Python SDK
  sends, is validated and treated as advisory. Empty, malformed or duplicate
  values return 400.

### JSON API

- Boolean query parameters also accept Python's `True` and `False` spellings.
  Other spellings, such as `TRUE`, `0` or `1`, still return 400.

### SDK scorecard

- Node.js, PHP and Python probes run alongside Go and Ruby over a shared,
  verified HTTPS transport. The runner records clean-source state and derived
  SDK metadata with each result, keeps early errors, and the PHP probe signs
  URLs for the final endpoint.

### Tests

- Test fixtures close catalog handles before removing their directories, and
  Unix runs now fail tests that leave files open, so Windows cleanup failures
  are caught on every platform.

## Compatibility and migration

The first start migrates the catalog from `PRAGMA user_version = 34` (0.4.0 and
0.4.1) to `35`, adding the invocation replay table. The migration is one-way:
after it runs, 0.4.1 and earlier releases refuse to open the data directory.
Back up the data directory before upgrading if you may need to roll back.
Upgrading from 0.3.0 or earlier also applies the
[0.4.0 migration](0.4.0.md#compatibility-and-migration).

- Media and multipart uploads with an invocation token but no
  `ifGenerationMatch` returned 501 in 0.4.1 and now succeed. A retry of a
  committed conditioned upload with the same token now returns the original
  object instead of 412. Tests that relied on either response need updating.
- PATCH and PUT bodies that change `acl` or `defaultObjectAcl` returned 400 in
  0.4.1 and now replace the ACL. Strict-mode callers without `setIamPolicy`
  now receive 403 for those fields; a caller with `getIamPolicy` can still echo
  the unchanged ACL.
- JSON media downloads of gzip-encoded objects without `Accept-Encoding: gzip`
  now return decompressed bytes. Send `Accept-Encoding: gzip` or set
  `Cache-Control: no-transform` to keep the stored bytes.
- Object metadata HEAD returned 405 in 0.4.1.

## Known limitations

- Invocation token replay covers media, multipart and JSON copy only; XML,
  resumable initiation, PATCH, DELETE, rewrite and compose retries execute
  again. The ten-minute retention and capacity limits are local choices, not
  Google's cache policy.
- Gzip expansion applies only to JSON media GET; XML downloads return the
  stored bytes. JSON media HEAD and collection HEAD are unsupported.
- The Node.js, PHP and Python results cover the scorecard's permissive,
  default-location HTTPS profile. Node.js V4 signing omits a nondefault port
  from the canonical host, so strict-mode signing at such an endpoint fails.
- The [0.4.0 known limitations](0.4.0.md#known-limitations) still apply.
