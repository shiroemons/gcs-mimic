# gcs-mimic 0.15.0

0.15.0 makes the server's command line work the way people already type it. `docker run IMAGE --scheme http` now starts the server, options can come in any order, and one or two hyphens and `--name value` or `--name=value` all mean the same. `--port`, `--port-http` and `--host` are documented options that change one part of a listener address. `FAKE_GCS_*` variables are no longer read, so read [Compatibility and migration](#compatibility-and-migration) before upgrading.

It publishes `ghcr.io/shiroemons/gcs-mimic:0.15.0` for `linux/amd64` and `linux/arm64`, mirrors the same digest to Docker Hub as `shiroemons/gcs-mimic:0.15.0`, and publishes native archives for all eight macOS, Windows and Linux targets. The [feature matrix](../feature-matrix.md) lists the exact supported subsets. Rows marked `PARTIAL` keep their listed missing cases.

## Changes

### Starting the server

- A command line whose first argument is an option runs `serve`, so `docker run IMAGE --scheme http` and a Compose `command` need no `serve`. The word `serve` is still accepted. The order of options no longer decides whether the server starts: `--scheme http --port 9000` used to fail while `--port 9000 --scheme http` started.
- Every server option takes one or two hyphens and a value after a space or `=`. `--listen`, `-listen`, `--listen=127.0.0.1:9000` and `-listen=127.0.0.1:9000` are the same option.
- `-h`, `--h`, `-help` and `--help` print the usage after any server options, and `-version` works like `--version`.
- `--help` lists the common options first.
- Running without arguments names the command to use.

### Listener options

- `--port`, `--port-http` and `--host` are documented options. They are flags only; `GCS_MIMIC_LISTEN` and `GCS_MIMIC_LISTEN_HTTP` remain the variables.
- `--port` and `--host` change one part of the listener address and keep the other. A port alone keeps the configured IP: `0.0.0.0` in the image, `127.0.0.1` for a native binary. A malformed configured address is reported under its own name.
- `--port-http` keeps the IP of `listen_http`, or else of `listen`. Without `scheme=both` it is ignored with a warning, and an explicit `--listen-http` stays an error.

### Startup messages

- A flag warns only when its translation leaves something to know: `-filesystem-root`, `-public-host`, `-cors-headers` and `-event.*`. Flags that behave as their native setting start without a warning.
- A server option given to a helper command such as `healthcheck` says it belongs to `gcs-mimic serve` and names the setting it would be.
- An empty `GCS_MIMIC_*` value names the Compose form that leaves it out.

### Fixes

- `--scheme http -public-host HOST` built an `https` public URL, because only the one-hyphen `-scheme` was consulted. The public URL now follows the effective scheme, however it was set.

### Documentation

- The README quick start begins with the command that needs no options and adds `--scheme http` as the next step, followed by a table of the common options with the port to publish.
- `llms.txt` names every server option with its variable and JSON key.
- [Option aliases](../slices/option-aliases.md) replaces the earlier legacy setting aliases page.

### Dependencies and project

- No dependency is added.
- The Rust build image pin follows the index rebuilt under its unchanged tag. Its `linux/amd64` and `linux/arm64` manifests are unchanged.

## Compatibility and migration

0.15.0 keeps catalog schema 52. A data directory that 0.14.0 used opens without a migration.

### Upgrade checklist

- **`FAKE_GCS_*` variables.** They have no effect, and nothing warns. With `FAKE_GCS_SCHEME=http` left in place the server stays on HTTPS, so HTTP clients fail to connect. Use the matching flag or `GCS_MIMIC_*` variable from the [migration guide](../migrate-from-fake-gcs-server.md#setting-equivalents). A JSON config file with such a key now fails as an unknown setting.
- **`--port` or `--host` on a native binary.** A port alone used to bind `0.0.0.0` and now stays on `127.0.0.1`. Add `--host 0.0.0.0` to accept other machines. The container image still binds `0.0.0.0`.
- **`-log-level trace`, `fatal` or `panic`.** They now fail, as `--log-level` already did and as fake-gcs-server does.
- **Repeated `-scheme`, `-backend` or `-log-level`.** Naming one of these twice now fails, because they are the native options. Other translated flags keep the last value.
- **An unknown `-backend` value.** It now fails with the native `backend must` message.
- **Parsers of diagnostics.** Flags with an exact translation no longer produce a warning, and the remaining ones start with `This option works differently here;`.

## Known limitations

- Helper commands such as `healthcheck`, `url` and `sync` accept only `--name VALUE`.
- `-public-host` still needs `GCS_MIMIC_COMPAT_PROFILE=legacy-emulator` for Host matching.
- The limitations listed for [0.14.0](0.14.0.md#known-limitations) still apply, and these changes do not close the [1.0.0 gate](../release-policy.md#the-100-gate).
