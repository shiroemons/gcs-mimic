# gcs-mimic 0.25.0

0.25.0 answers XML API version 2 object listings and XML multipart uploads as Cloud Storage answered them on 2026-11-16, in two differential cases recorded against Cloud Storage and replayed offline. Existing commands, options, environment variables and configuration values keep their meaning; the answers that change are listed under [What may need attention](#what-may-need-attention).

It publishes `ghcr.io/shiroemons/gcs-mimic:0.25.0` for `linux/amd64` and `linux/arm64`, mirrors the same digest to Docker Hub as `shiroemons/gcs-mimic:0.25.0`, and publishes native archives for all eight macOS, Windows and Linux targets. The [feature matrix](../feature-matrix.md) lists the exact supported subsets.

## What may need attention

- **The catalog moves to schema 54, and 0.24.0 cannot open it afterwards.** The first start of 0.25.0 on a data directory adds two columns that keep XML multipart upload and part times with microseconds, in one transaction. 0.24.0 and earlier releases refuse a data directory at schema 54, so back up a data directory you may want to open with an earlier release.
- **Successful XML multipart answers are `text/html; charset=UTF-8`.** Initiation, the upload listing, the part listing, completion and the empty answer to a part upload carry `text/html; charset=UTF-8`, as Cloud Storage sends them; 0.24.0 sent `application/xml`. An abort's 204 has no `Content-Type`, and errors stay `application/xml`. A client that chooses its parser by the content type has to read these as XML.
- **`list-type=2` listings change shape.** `MaxKeys` is written only when the request sent `max-keys`, entries have no `StorageClass`, `KeyCount` counts the entries but not the common prefixes, and `encoding-type=url` writes a space as `+` and keeps `/`. An empty `continuation-token`, which 0.24.0 refused with 400, now lists from the start.
- **Multipart upload listings echo only what was sent.** `Prefix` and `Delimiter` appear only when the request sent them, both next markers are always present, and an `upload-id-marker` without a `key-marker` is ignored instead of refused.

## Changes

### XML object listing

- A `list-type=2` listing writes `Name`, `Prefix`, `StartAfter` and `ContinuationToken` when sent (even empty), `NextContinuationToken` on a truncated page, `KeyCount`, `MaxKeys` when sent, `Delimiter`, `IsTruncated` and `EncodingType`, then entries without `StorageClass` and common prefixes. `KeyCount` counts the entries only.
- An empty `continuation-token` counts as absent: the page starts at the beginning, or after `start-after` when that is sent, and the empty token is echoed. A token gcs-mimic did not issue answers 400 `InvalidArgument` with the message `Invalid argument.` and the details `Invalid page token.`.
- `encoding-type=url` on version 2 encodes names form style: a space becomes `+` and `/` stays. Version 1 keeps its percent encoding, which was not recorded. See [XML object listing](../slices/xml-object-list.md).

### XML multipart upload

- The upload listing writes `Bucket`, `KeyMarker`, `UploadIdMarker`, `NextKeyMarker`, `Prefix` and `Delimiter` when sent, `NextUploadIdMarker`, `MaxUploads` and `IsTruncated`, then uploads and common prefixes. Both next markers are present and empty on the last page. It accepts `encoding-type=url`, with `EncodingType` last; another value answers 400 `InvalidArgument` naming it.
- The part listing writes `NextPartNumberMarker` after `PartNumberMarker` on every page, 0 on the last.
- `Initiated` and part `LastModified` carry six fractional digits, from microseconds the catalog now keeps. Uploads and parts written before the upgrade report zero microseconds past their millisecond; the seven-day expiry is unchanged.
- Both listings send `Cache-Control: private, max-age=0` with `Expires`. Completion sends `x-goog-stored-content-length` and no `ETag` header beside the document's, and its `Location` uses `http` whatever the request's scheme, as Cloud Storage answered an `https` request. XML POST answers vary by `Origin`, like PUT and DELETE. See [XML multipart upload](../slices/xml-multipart-upload.md).

### Differential harness

- A case can capture the text of an XML element (`xml:ELEMENT`), an XML document sent as `text/html` is compared as a tree, and cleanup and the sweep abort open XML multipart uploads before deleting a bucket.
- The local server advertises `https://api.storage.invalid` as its API base, so a link Cloud Storage writes as `http` on purpose is compared.
- The [reference](../../../compatibility/differential/reference/gcs.json) adds `xml-list-v2` and `xml-multipart-list`, recorded with 65 requests; all 124 cases replay without a difference. The [evidence page](../evidence/xml-listing-provider-probe.md) keeps the curl observations beside the harness recording.

## Compatibility and migration

A data directory from 0.8.0 through 0.24.0 is migrated to catalog schema 54 when 0.25.0 first opens it; afterwards only 0.25.0 or later opens it. The migration adds columns with a default and changes no stored value, and no data directory is reset.

A `gcs-mimic sync` command and the server it manages must still be the same release, so upgrade both together. The Go packages accept a binary of the same minor release, so upgrade the Go module to 0.25.0 together with the binary.

## Dependencies and project

- No Rust dependency, Rust toolchain or container base changes. The Go module requires `cloud.google.com/go/storage` v1.71.0, as do the Go SDK suite and scorecard; `go mod tidy` raised only indirect requirements. The PHP suite and scorecard pin the rebuilt `composer:2.11.2` index, whose linux/amd64 and linux/arm64 manifests are unchanged. The package version and the Go module's `ModuleVersion` move to `0.25.0`, and the recipes pin `0.25.0`.
- The released-data fixture for 0.24.0 joins the upgrade test, so data directories from 0.8.0 through 0.24.0 are opened by the new build.
- The [feature ledger](../../../compatibility/features.json) records the recorded answers on EXT-XML-003, 004, 011, 013, 019, 020 and 023, which stay `PARTIAL`, and the [gap ledger](../../../compatibility/gaps.json) resolves SPEC-XML-LIST-V2, SPEC-XML-MULTIPART-LIST and SPEC-XML-MULTIPART-CONTENT-TYPE.

## Known limitations

- The released-data fixture for 0.25.0 is added after publication, as for earlier releases.
- Only a space and `/` were recorded under `encoding-type=url`; other characters follow application/x-www-form-urlencoded by assumption. A page that both echoes and issues a continuation token, the next part number marker of a truncated part page and XML POST requests other than multipart initiation and completion were not recorded either; the ledger names each local choice.
- The limitations listed for [0.24.0](0.24.0.md#known-limitations) still apply, and these changes do not close the [1.0.0 gate](../release-policy.md#the-100-gate).
