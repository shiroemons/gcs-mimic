# gcs-mimic 0.2.0

0.2.0 adds an opt-in gRPC listener for Storage v2 and the legacy Storage v1
migration profile, bucket and object policies that the Go and Ruby SDKs use,
and HTTP/1.1 connection behavior closer to Cloud Storage: persistent
connections and documented, retryable timeout responses. It publishes
`ghcr.io/shiroemons/gcs-mimic:0.2.0` for `linux/amd64` and `linux/arm64` and
native archives for all eight macOS, Windows and Linux targets. The
[0.1.0 release notes](https://github.com/shiroemons/gcs-mimic/blob/v0.1.0/docs/en/releases/0.1.0.md)
describe the base workflows; the [feature matrix](../feature-matrix.md) lists
the exact supported subsets.

Upgrading migrates the data directory to a schema that 0.1.x cannot open, and
several responses change. Read [Compatibility and migration](#compatibility-and-migration)
before upgrading.

## Changes

### gRPC

- `--grpc-listen` (`GCS_MIMIC_GRPC_LISTEN`, JSON `grpc_listen`) starts an
  optional plaintext h2c listener for `google.storage.v2.Storage`. It serves
  bucket CRUD, updates, IAM and retention locking; object metadata, media,
  listing, deletion and restore; resumable writes; rewrite, compose and move;
  and bidirectional ranged reads through the same catalog and authorization
  as JSON. CancelResumableWrite, Rapid append, unsupported fields and other
  RPCs return non-retryable `UNIMPLEMENTED` with `ErrorInfo`. Point Go clients
  at it with `STORAGE_EMULATOR_HOST_GRPC`.
- The same listener serves the twelve legacy Storage v1 RPCs of the reference
  emulator as a migration profile, without a Google GA fidelity claim.
- Idle gRPC connections close with GOAWAY, dead peers are detected with
  HTTP/2 keepalive, and an open stream silent for 60 seconds is closed.

### Buckets

- Uniform bucket-level access, including the 90-day lock and rejection of ACL
  parameters while it is enabled.
- Retention policies with locking, enforced on deletes and overwrites.
- Soft delete policies, with deleted and replaced generations kept until their
  hard-delete time.
- Lifecycle rules are validated, stored and returned; they are not executed.
- Regional and predefined dual-region location names in bucket creation,
  `default_location` and the bucket initializer. Physical placement is not
  simulated.
- `buckets.testIamPermissions` answers with the authorization real operations
  use.

### Objects

- Temporary holds and monotonic `customTime`.
- `objects.restore` of soft-deleted generations and `softDeleted` listings.
- Atomic same-bucket `objects.move` that reuses the stored bytes.
- `matchGlob` filtering for JSON object listings.

### Authentication

- Path-style legacy V2 RSA signed URLs for GET and PUT. Strict mode verifies
  them with registered keys; permissive mode ignores credentials as it does
  for V4.

### Directory synchronization

- The synchronized directory is scanned after readiness: external creates,
  edits and rename targets are ingested with inherited metadata, and buckets
  deleted through the API are not recreated from leftover directories.
  External deletions are not yet ingested.

### HTTP behavior

- HTTP/1.1 connections stay open between requests. An idle connection closes
  after the new `keep_alive_timeout_ms` (`--keep-alive-timeout-ms`,
  `GCS_MIMIC_KEEP_ALIVE_TIMEOUT_MS`; default 120000, range 1–600000), or at
  once when every `max_connections` slot is taken.
- A deadline that expires before a response now returns
  408 `uploadBrokenConnection` for object uploads and 503 `backendError` for
  other requests, instead of closing the connection without a response.
- After an early rejection the server keeps reading the rest of the request
  body for up to 30 seconds, so clients read the rejection instead of a reset.
- Recognized but unsupported inputs return 400 `badRequest` (XML:
  400 `InvalidArgument`) instead of 501, so SDKs stop retrying them.
- No-op defaults sent by the Ruby SDK, such as an empty
  `X-Upload-Content-Type`, are accepted.
- A media read failure after the response headers is logged as
  `object_body_read_failed` with its cause.

### Distribution and tooling

- `SHA256SUMS` uses LF line endings for every entry, so macOS
  `shasum --check` verifies the Windows archives too.
- The daily dependency freshness check handles Go modules that publish only
  pseudo-versions. Dependencies were refreshed, including tonic 0.14.8 and
  the rebuilt `rust:1.99.1-slim-trixie` base image.

## Compatibility and migration

- **Back up the data directory before upgrading.** On first start, 0.2.0
  migrates it from schema 21 (`PRAGMA user_version = 21`, used by 0.1.0
  through 0.1.3) to schema 27. 0.1.x releases refuse to open the migrated
  directory with `unsupported catalog schema version`; downgrading requires
  the backup.
- Responses for recognized but unsupported inputs change from 501 to 400, and
  known Google JSON routes that are not implemented, such as ACLs,
  notifications and HMAC keys, change from 404 to the same 400. Missing
  resources and unknown paths still return 404.
- Bucket `PUT` (`buckets.update`) now keeps omitted settings instead of
  resetting them; explicit `null` and empty values keep their field rules.
- Clients that read a response until the server closes the connection must
  send `Connection: close` or use the response's Content-Length. SDKs and
  standard HTTP clients already do.
- With `max_connections` of 1, a connection closes after each response,
  because an idle connection gives up the only slot.
- `sync_dir` is rejected at startup under strict authentication. Directory
  synchronization remains unavailable on Windows.

## Verification

The [release workflow](https://github.com/shiroemons/gcs-mimic/blob/v0.2.0/.github/workflows/binaries.yaml)
