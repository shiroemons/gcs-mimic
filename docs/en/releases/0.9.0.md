# gcs-mimic 0.9.0

0.9.0 makes `gcloud storage` usable against gcs-mimic, adds runnable examples for eight official client libraries and the gcloud CLI, and aligns JSON responses with a live Cloud Storage recording: replaying the committed reference now matches all 59 differential cases, down from 186 differing fields at 0.8.0. Several of these alignments change behavior that the [0.8.0 release notes](0.8.0.md) documented, such as the resumable cancellation answer and the object PUT projection; read [Compatibility and migration](#compatibility-and-migration) before upgrading.

It publishes `ghcr.io/shiroemons/gcs-mimic:0.9.0` for `linux/amd64` and `linux/arm64`, mirrors the same digest to Docker Hub as `shiroemons/gcs-mimic:0.9.0`, and publishes native archives for all eight macOS, Windows and Linux targets. The [feature matrix](../feature-matrix.md) lists the exact supported subsets. Rows marked `PARTIAL` keep their listed missing cases.

## Changes

### gcloud storage

- `GET /storage/v1/b/{bucket}/storageLayout` (`buckets.getStorageLayout`) returns `kind`, `bucket`, `location` and `locationType` from the bucket resource and requires `storage.objects.list` in strict mode. Google Cloud SDK 591.0.0 reads it before every `gcloud storage cp` and `cat`. See [bucket storage layout](../slices/bucket-storage-layout.md).
- `objects.list` and gRPC v2 `ListObjects` accept `includeFoldersAsPrefixes=true` with delimiter `/`, which `gcloud storage ls` sends. Local buckets hold no folders or managed folders, so the listing is the same as without the flag; any other or missing delimiter answers 400 `invalidParameter` (gRPC `INVALID_ARGUMENT`).
- JSON `multipart/related` uploads and fixture uploads accept the gcloud (apitools) multipart shape that gcloud sends for files below 8 MiB: a single-quoted boundary and LF-only framing, decided per body. XML POST Object forms keep strict CRLF framing and RFC quoting. See the [gcloud request shape](../slices/json-object-multipart.md#gcloud-request-shape).
- A path-style `POST /resumable/upload/storage/v1/b/{bucket}/o` with an `uploadType` parameter, the Discovery resumable protocol path where gcloud starts stdin uploads and files of 8 MiB or more, is served as the resumable initiation on `/upload/storage/v1`. Other methods, requests without `uploadType` and virtual-hosted requests keep their XML meaning. See the [Discovery resumable protocol path](../slices/resumable-upload.md#discovery-resumable-protocol-path).
- With these, the gcloud example below creates a bucket, uploads a file, stdin, a resumable upload and a parallel composite upload, lists, describes, downloads (including a sliced download) and deletes objects and the bucket. This is a documented example subset; the broader gcloud integration row (`AUDIT-005`) stays `NOT_STARTED`.

### Examples

- [`examples/`](../../../examples/README.md) runs the same create, upload, list, download and delete workflow with the official Go, Ruby, Node.js, Python, PHP, Java, .NET and Rust clients and with `gcloud storage`, each with pinned versions, a lockfile where the ecosystem has one and a `./run.sh` (`./gcloud-example.sh` for gcloud). The README adds a connection snippet for each client.

### JSON API alignment with Cloud Storage

- Resumable cancellation, session errors, object update projection, upload error headers, ACL validators and ordering, bucket versioning, error locations, move permission messages and stored-gzip download framing now follow the 2026-11-01 and 2026-11-02 Cloud Storage recordings. Each change is listed under [Behavior changes in detail](#behavior-changes-in-detail).
- `gcs-mimic import fake-gcs-server` keeps an absent source versioning setting unset and preserves an explicit `true` or `false`; a source versioning value of another type is rejected.

### Differential harness

- The committed reference combines 58 cases recorded live on 2026-11-01 with `obj-resumable` re-recorded on 2026-11-02, and the offline replay matches all 59 cases. See the [harness verification](../evidence/differential-harness.md) and the [comparison report](../evidence/differential-comparison.md).
- `cargo xtask differential merge` refreshes single cases: it merges a partial live recording into the reference by case ID, keeps every other case and its order, records every contributing date, and refuses self-check or empty recordings, failed cases and mismatched tool metadata. Request fingerprints are canonical across standalone and workspace builds, and the notification case checks topics through a loopback Pub/Sub stand-in. See [development](../development.md).

- The README introduces the mascot, Micket.
- On macOS the test wrapper uses the normal `TMPDIR` and a serial pool by default, like CI; `GCSM_TEST_RAMDISK=1` opts in to the RAM disk, which is released even when processes still hold it. See [development](../development.md).

## Compatibility and migration

0.9.0 raises the catalog schema from 48 (0.8.0) to 49, which records whether a bucket's versioning was configured. The first start of 0.9.0 migrates an existing data directory automatically and logs the versions. The migration is one-way: back up the data directory before upgrading, and do not open it with 0.8.0 afterwards. Upgrading from 0.7.0 or earlier also applies the [0.8.0 migration](0.8.0.md#compatibility-and-migration).

### Upgrade checklist

These changes most often require updates to tests or clients; the full list follows below.

- **Back up and migrate.** The catalog moves to schema 49 on first start and cannot be reopened by 0.8.0.
- **Resumable cancellation is JSON.** Cancelling a JSON resumable session answers 499 with a `clientClosedRequest` JSON error envelope, and later requests on that session repeat it, where 0.8.0 answered plain text and then 410. Clients that checked for 410 after a cancel must expect 499.
- **Object PUT omits ACLs.** An object update (PUT) response omits `acl` and `owner` unless the request carries `projection=full`; 0.8.0 answered with the full projection.
- **`versioning.enabled: false` stays visible.** A bucket whose versioning was explicitly disabled now reports `versioning: {"enabled": false}` instead of omitting `versioning`.

### Behavior changes in detail

- Resumable uploads: a JSON cancellation answers 499 with a `clientClosedRequest` JSON error envelope instead of plain text, and later status, write and cancel requests on the cancelled session repeat that 499 until the session's original seven-day deadline (404 afterwards), where 0.8.0 answered 410. Sessions cancelled or aborted by validation under 0.8.0 cannot be told apart and both answer the 499 envelope after the upgrade until their deadline; sessions aborted after the upgrade keep 410. See [resumable uploads](../slices/resumable-upload.md).
- Resumable uploads: a session that received a syntactically unparsable `Content-Range` is terminal, and later requests repeat the plain-text 400 the recording shows; the terminal state survives a restart. Duplicate `Content-Range` headers, offsets or totals that disagree with the session, and an undersized nonfinal chunk stay retryable 400 errors.
- Object update (PUT) responses use the `noAcl` projection unless `projection=full` is given, also when the body carries `acl` and in the legacy-emulator profile. The 0.8.0 notes said an object PUT response stays `full`; the recording returned neither `acl` nor `owner`. See [object metadata](../slices/json-object-metadata.md).
- Upload errors no longer send `x-content-type-options: nosniff`, which the 0.8.0 notes said they kept. JSON error envelopes labelled `text/html` escape `<`, `>` and `&` as JSON Unicode escapes instead, so request input is never read as markup and the decoded message is unchanged.
- ACLs: bucket, default object and object ACL list and entry delete responses send a bare `etag` header. Entries keep insertion order, so a deleted and re-added entry moves to the end, and the order (including the owner's position) survives a restart. An entry's `selfLink` keeps `@` in the entity unencoded instead of `%40`. See [JSON ACLs](../slices/json-acl.md).
- Bucket versioning: once `versioning.enabled` is set to `false`, bucket resources keep reporting it, also after a restart; buckets without a versioning setting still omit it, and a null `versioning` member or a native PUT that omits it clears the setting. Buckets disabled before the schema 49 migration stay omitted, because the old storage cannot show whether the setting was ever made. See [versioning and holds](../slices/bucket-versioning-holds.md).
- JSON errors: an object metadata request whose `If-Match` header fails answers 412 with `location: "If-Match"`, `locationType: "header"` and the object's current `etag` header; a compose source precondition failure names `If-Match` the same way; an invalid bucket `predefinedAcl` names `predefinedAcl` with `locationType: "parameter"`.
- Moving a missing source object answers 403 with a message that names the caller instead of `Caller`: the local creator email in the permissive profile, the registered principal's email in strict mode, and `Anonymous caller` for anonymous requests. Without a valid email (for example with an empty local creator), the generic permission error is returned; internal principal IDs are never shown. See [object move](../slices/sdk-object-move.md).
- Private JSON media GETs of an object stored with gzip content encoding (a nonempty body that starts with the gzip magic bytes) use chunked framing without `Content-Length`, also for ranges. When the object's `Cache-Control` is `no-transform`, the response's private cache policy ends with `no-transform`. Public objects, `HEAD`, empty objects, plain bodies declared as gzip and XML downloads keep their framing. See the [media read observations](../evidence/media-read-provider-observations.md).
- `buckets.getStorageLayout` and `includeFoldersAsPrefixes=true` with delimiter `/` used to answer 400 badRequest as recognized unsupported features; they are now served as described above. The SDK fail-fast probes that relied on them now send Requester Pays `userProject` instead.
- A path-style `POST` to `/resumable/upload/storage/v1/b/{bucket}/o` with an `uploadType` parameter is now an upload initiation; before, it was an XML request for an object in a bucket named `resumable`. The same request without `uploadType` keeps its XML meaning.

## Known limitations

- The four gcloud-driven behaviors (`buckets.getStorageLayout`, `includeFoldersAsPrefixes`, the gcloud multipart framing and the `/resumable/upload` initiation path) follow the official references and the requests Google Cloud SDK 591.0.0 sends, but are not yet verified against a live Cloud Storage recording. The storage layout reports the bucket's own `locationType` (for example `multi-region` for `US`), although the reference describes `region`; `JSON-BUCKETS-004` and `BEHAVIOR-OBJECT-020` stay `PARTIAL`.
- `gcloud storage rm -r gs://BUCKET` is not supported, because gcs-mimic has no managed folders API. Delete the objects with `gcloud storage rm "gs://BUCKET/**"` and then the bucket with `gcloud storage buckets delete gs://BUCKET`, as the [gcloud example](../../../examples/gcloud/README.md) does.
- The examples are not yet run by CI or covered by the daily dependency update detection; their pinned client versions can fall behind.
- Duplicate `Content-Range` headers, offsets that disagree with the session and other unrecorded resumable errors remain local choices; the recording does not establish every invalid-range, terminal-retention or lifetime boundary.
- An object PUT whose body carries `acl`, and the legacy-emulator profile's object PUT, default to `noAcl` without a live recording of those shapes. A full ACL replacement does not preserve the owner entry's position.
- Migrating the versioning state of soft-deleted buckets to schema 49 has no test coverage.
- The stored-gzip framing follows the 2026-11-01 recording; an earlier observation with different framing cannot be reconciled offline, and broader provider framing parity remains unverified.
- The differential harness covers its 59 declared cases and normalized fields; it does not establish unrestricted Cloud Storage API parity, and these additions do not close the [1.0.0 gate](../release-policy.md#the-100-gate).
