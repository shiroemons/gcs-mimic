# gcs-mimic 0.16.0

0.16.0 closes five request-handling gaps that real clients run into. Signed URLs from `gsutil signurl` and `gcloud storage sign-url` verify, anonymous gsutil works, XML writes apply `x-goog-acl`, batch requests accept the framing Cloud Storage accepts, and AWS-signed XML requests can use `x-amz-*` headers. Each behavior was first observed on Cloud Storage and is recorded in the differential suite. A PATCH with an empty `metadata` map now clears it, so read [Compatibility and migration](#compatibility-and-migration) before upgrading.

It publishes `ghcr.io/shiroemons/gcs-mimic:0.16.0` for `linux/amd64` and `linux/arm64`, mirrors the same digest to Docker Hub as `shiroemons/gcs-mimic:0.16.0`, and publishes native archives for all eight macOS, Windows and Linux targets. The [feature matrix](../feature-matrix.md) lists the exact supported subsets. Rows marked `PARTIAL` keep their listed missing cases.

## Changes

### Signed URLs

- V4 query signatures accept `X-Goog-*` and `X-Amz-*` parameter names in any ASCII case, so URLs from `gsutil signurl` and `gcloud storage sign-url`, which send them in lowercase, verify.
- The canonical query keeps the spelling that was sent, so a URL signed with its names in another case answers 403 `SignatureDoesNotMatch`.
- A parameter repeated in another case answers 400 `ExcessHeaderValues`. V2 parameter names stay exact.

### XML API

- `x-goog-acl` on PUT, resumable and multipart initiation and copy applies a canned ACL with the same rules as the JSON `predefinedAcl`. It takes the XML names, such as `project-private`.
- A JSON spelling or an unknown `x-goog-acl` value answers 400 `InvalidArgument` with `Invalid canned acl: VALUE`. Uniform bucket-level access answers 400 with the legacy ACL message.
- Under an AWS signature (AWS4 header or query, or V2 `AWS`), `x-amz-*` headers with an `x-goog-*` equivalent are applied, and reads return custom metadata as `x-amz-meta-*`. Other `x-amz-*` headers are ignored.
- Sending both spellings of one header under an AWS signature answers 400 `ExcessHeaderValues`.
- Without an AWS signature, `x-amz-*` headers are ignored, and `x-amz-copy-source` answers 400 `Missing copy source`.

### JSON API

- Every route accepts and discards the `key` parameter. It never authenticates a caller. Anonymous gsutil sends it on every request.
- Object reads accept `response-content-disposition` and `response-content-type` without applying them.
- Custom metadata numbers and booleans are stored as text in the form Cloud Storage writes. Object and array values are dropped while the other keys apply.
- A PATCH clears the custom metadata when its `metadata` map is empty or every value in it is dropped.
- An object written with a predefined ACL lists its owner first, through JSON and XML.

### Batch

- A batch body may use LF-only lines, omit the blank line after a part's inner headers, or put a request line directly before the delimiter. The opening delimiter selects the line ending, so an LF-only boundary line inside a CRLF envelope stays body content.

## Compatibility and migration

0.16.0 keeps catalog schema 52. A data directory that 0.15.0 used opens without a migration.

### Upgrade checklist

- **A PATCH with an empty `metadata` map.** It used to leave the custom metadata unchanged and now clears it. Omit the field to leave the metadata alone.
- **Tests that expect an error.** XML `x-goog-acl` and `x-amz-*` headers, the JSON `key` and `response-content-*` parameters and non-string custom metadata values used to be refused. They now behave as listed above.
- **The order of ACL entries.** New objects written with a predefined ACL list the owner first. Objects already stored keep their order, and an object that inherits the default ACL still lists the owner last.

## Known limitations

- gcs-mimic has no API key registry, so it treats every `key` as valid. Cloud Storage answers 400 `keyInvalid` to an anonymous request with a key it does not recognize.
- `x-amz-server-side-encryption-customer-*` headers stay refused.
- The work described in the research notes above is not part of this release.
- The limitations listed for [0.15.0](0.15.0.md#known-limitations) still apply, and these changes do not close the [1.0.0 gate](../release-policy.md#the-100-gate).
