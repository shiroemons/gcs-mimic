# gcs-mimic 0.4.1

0.4.1 is the first published release with the
[0.4.0 changes](0.4.0.md): JSON ACL resources, project HMAC keys and the
service agent, bucket notification configurations, Autoclass, storage class on
write, object retention, customer-supplied encryption keys, V4 signed POST
policy uploads and gRPC appendable objects. The `v0.4.0` tag exists, but its
Windows release builds failed a test cleanup, so nothing was published for it.
0.4.1 adds one security fix on top. It publishes
`ghcr.io/shiroemons/gcs-mimic:0.4.1` for `linux/amd64` and `linux/arm64`,
mirrors the same digest to Docker Hub as `shiroemons/gcs-mimic:0.4.1`, and
publishes native archives for all eight macOS, Windows and Linux targets. The
[0.3.0 release notes](https://github.com/shiroemons/gcs-mimic/blob/v0.3.0/docs/en/releases/0.3.0.md)
describe the previous published release.

Upgrading from 0.3.0 migrates the data directory to a catalog schema that
0.3.0 cannot open. Read the
[0.4.0 compatibility and migration notes](0.4.0.md#compatibility-and-migration)
before upgrading a persistent deployment.

## Changes since 0.4.0

### Security

- PATCH and PUT accept an `acl` or `defaultObjectAcl` field that repeats the
  stored ACL only when the caller may read that ACL. In strict mode, a caller
  with update permission but without the matching `getIamPolicy` permission
  could previously tell whether a guessed ACL matched the stored one, because a
  match was accepted and anything else was rejected. Such callers now get the
  same 400 response whatever the stored ACL is. Permissive mode is unaffected.

### Tests

- Four object retention wire tests now stop their server before the test
  directory is removed. Windows cannot delete files the catalog still holds,
  which made the 0.4.0 Windows release builds fail.

## Compatibility and migration

0.4.1 uses the same catalog schema, 34, as the unpublished 0.4.0. From 0.3.0
or earlier, follow the
[0.4.0 compatibility and migration notes](0.4.0.md#compatibility-and-migration):
the first start migrates the catalog from schema 27 one-way, so back up the data
directory if you may need to roll back.

Strict-mode clients that echoed an unchanged ACL in PATCH or PUT without
`getIamPolicy` permission now receive 400; drop the field or grant the
permission.

## Verification

The [release workflow](https://github.com/shiroemons/gcs-mimic/blob/v0.4.1/.github/workflows/binaries.yaml)
creates this Release only after `validate`, including the dependency freshness
check, Foundation and all eight native build/test jobs succeed at the tag's
SHA. The
[container workflow](https://github.com/shiroemons/gcs-mimic/blob/v0.4.1/.github/workflows/ghcr.yaml)
then builds both Linux architectures natively, verifies their SBOM and
provenance, publishes the multi-architecture tag and checks anonymous pulls,
and the Docker Hub workflow mirrors that digest.

Before the release commit, all Rust test binaries, format, clippy and the
compatibility ledger check passed locally on macOS, and the Foundation checks,
including the Windows portability tests, passed in CI at the commit that
carries both fixes. The 0.4.0 notes record the earlier SDK suite, container
smoke and [SDK scorecard](../../../sdk-scorecard/results/2026-10-29-2/summary.md)
results; the fixes since then change only ACL echo handling and test cleanup.

## Known limitations

The [0.4.0 known limitations](0.4.0.md#known-limitations) still apply.
