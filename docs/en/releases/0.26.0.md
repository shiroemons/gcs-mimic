# gcs-mimic 0.26.0

0.26.0 answers object writes, resumable sessions, derived writes, storage classes and Storage v2 requests as Cloud Storage answered them in differential recordings up to 2026-11-17, replayed offline; the reference grows by 23 cases. It derives a number for every project instead of rendering 0, restarts a bucket retention period when an event-based hold is released, and asks `gcs-mimic buckets new` by goals. Existing commands, options, environment variables and configuration values keep their meaning; the answers that change are listed under [What may need attention](#what-may-need-attention).

It publishes `ghcr.io/shiroemons/gcs-mimic:0.26.0` for `linux/amd64` and `linux/arm64`, mirrors the same digest to Docker Hub as `shiroemons/gcs-mimic:0.26.0`, and publishes native archives for all eight macOS, Windows and Linux targets. The [feature matrix](../feature-matrix.md) lists the exact supported subsets.

## What may need attention

- **The catalog moves to schema 57, and 0.25.0 cannot open it afterwards.** The first start of 0.26.0 on a data directory migrates it in order: schema 55 renames stored project teams numbered 0, schema 56 adds the running digest of resumable sessions, and schema 57 adds the time an event-based hold was released. 0.25.0 and earlier releases refuse a data directory at schema 57, so back up a data directory you may want to open with an earlier release.
- **Projects have numbers.** 0.25.0 rendered every named project as number 0: `projectNumber` `"0"`, `project-owners-0` and `service-0@gs-project-accounts.iam.gserviceaccount.com`. A project ID of decimal digits is now that number, and any other ID renders a stable twelve-digit number derived from its SHA-256 (`local` is `902648055030`). A test that compares a team entity, a service agent address or a Storage v2 `projects/0` has to use the derived number; Storage v2 `projects/0` is now refused with `INVALID_ARGUMENT`. The fake-gcs-server profile keeps `projectNumber` `"0"`, but its ACL entities carry the derived number.
- **Metadata writes ignore `If-Match` and stale output fields.** JSON object metadata PATCH, PUT and POST PATCH override accept `If-Match` without evaluating it, where 0.25.0 answered a stale entity tag with 412, and ignore a body `etag`, `metageneration` and `updated`, which 0.25.0 refused when they no longer matched the object. Only the query conditions guard a concurrent update, as on Cloud Storage.
- **Requests that 0.25.0 served are refused.**
  - A soft-deleted listing, read or restore on a bucket without a soft delete policy answers 400 `invalid`; 0.25.0 answered an empty listing or 404.
  - A resumable initiation whose metadata `contentType` disagrees with `X-Upload-Content-Type` answers 400 and starts no session.
  - An XML HEAD of a customer-encrypted object without its key answers 400 `ResourceIsEncrypted`, as the GET does.
  - A bucket PATCH naming `rpo` on a regional bucket answers 400 `invalid`, and `MULTI_REGIONAL` is refused in a region bucket with Cloud Storage's class and location message.
  - A JSON resumable chunk with an open total that runs past the session's declared total fails the whole session, and every later request repeats the refusal.
  - `gcs-mimic buckets new` refuses a CORS rule without an origin or a method with exit 1 instead of writing it.
- **Answers that change shape.**
  - A DELETE of a completed JSON resumable session answers 200 with the object, where 0.25.0 answered 410.
  - A resumable 308 after data carries `x-goog-running-hash` and `x-range-md5`.
  - Resumable completions, their status requests and rewrites sent with `projection=full` carry `acl` and `owner`.
  - An initiation on `/resumable/upload/storage/v1` returns a session URI on the same alias.
  - An upload naming `predefinedAcl` under uniform bucket-level access answers reason `invalid` with Cloud Storage's message instead of `invalidArgument`.
  - In the native profile, an undeclared query parameter on object, bucket and default object ACL methods, bucket IAM, notifications, HMAC keys, the service account, `objects.move`, `objects.restore` and the managed folder list is ignored; 0.25.0 answered 400 `invalidParameter`. The fake-gcs-server profile ignores one only on the routes fake-gcs-server v1.56.1 serves.
  - An XML path whose bucket segment no bucket can be named answers XML 400 `InvalidBucketName`, or 404 `NoSuchBucket` when it decodes to a name with a slash, instead of the JSON router's 404.
  - Storage v2 `UpdateObject` with the `metadata` mask merges the request's entries into the stored map, and Storage v2 bucket times are floored to the millisecond.
- **Interactive `gcs-mimic buckets new` asks different questions.** It asks how gcs-mimic runs, the bucket names, whether each bucket is public or private, and what the buckets are for. Only strict mode keeps a bucket private and the mode is the whole server's, so one private bucket writes strict mode's settings, which move the application's servers to the trusted port 4444. `env` and `compose` write buckets without settings as their names alone, `compose` puts one bucket on each line, and a CORS list keeps each value once.

## Changes

### Object writes

- Every JSON write stores an empty `contentLanguage`, `contentDisposition`, `contentEncoding` and `cacheControl`, which copies and rewrites inherit; an empty `contentLanguage` is no longer refused. An empty XML header still leaves its field unset.
- A multipart media part declared `7bit`, `8bit` or `quoted-printable` is stored byte for byte; `base64` is still decoded.
- An empty custom metadata key is stored over JSON, XML (`x-goog-meta-`), Storage v2 and legacy v1, and a JSON `null` removes it.
- Object PATCH and PUT apply `predefinedAcl`, with Cloud Storage's refusal under uniform bucket-level access; naming both `predefinedAcl` and an `acl` body is refused, since no recording shows which wins. See [metadata `If-Match`](../slices/json-metadata-if-match.md) and the [JSON ACL contract](../slices/json-acl.md).

### Copy, rewrite, compose and move

- Copy, rewrite and compose apply `temporaryHold`, `customTime`, a `retention` and `destinationPredefinedAcl` on the destination; an anonymous caller cannot name the canned ACL. A rewrite session keeps these options for its continuations.
- `objects.move` with `projection=full` renders the moved object's ACL, which the move keeps from its source.
- Copies, rewrites and composes check that the copied bytes reproduce the source's recorded digests; damaged stored bytes are reported as corruption rather than as a checksum the client sent.

### Resumable uploads

- Each session keeps a running CRC32C and MD5 of its persisted bytes, saved with the offset so a restart resumes them; sessions staged by an earlier release report no digests and still complete.
- Sessions started on the Discovery alias `/resumable/upload/storage/v1` serve chunk, status and final requests on that alias. `X-Goog-Hash` on an initiation is ignored; the final request still verifies it. See [resumable upload](../slices/resumable-upload.md).
- The `acl` and `owner` in a completed session's answers are read with the initiator's permissions, so a strict-mode initiator that may not read the object's ACL receives neither.

### Projects, storage classes and retention

- Project numbers render in JSON `projectNumber`, Storage v2 `projects/{number}`, the legacy v1 `project_number`, project team entities and the service agent address. A request may name its project by number on the JSON `project` parameter and path, the XML `x-goog-project-id` header and the Storage v2 and legacy v1 project fields, and bucket and HMAC key page tokens continue under either spelling. See [project numbers](../slices/project-numbers.md).
- The legacy `REGIONAL` class is stored in a region bucket, and every request naming a class its bucket's location cannot hold is refused as Cloud Storage refuses it, over JSON, XML and Storage v2. Lifecycle transitions add `DRA` to `REGIONAL` and `REGIONAL` to `NEARLINE`, `COLDLINE` and `ARCHIVE`. See [bucket storage classes](../slices/bucket-autoclass-storage-class.md).
- A bucket retention period counts from the later of creation and the last release of an event-based hold, and no expiration is reported while the hold is held, as the pinned googleapis protos describe. Generations whose hold was released before the upgrade keep counting from creation. See [retention policy](../slices/sdk-retention-policy.md).

### Storage v2 and legacy v1

- `UpdateObject` applies `predefined_acl`; `ComposeObject` and `RewriteObject` apply `destination_predefined_acl`, a temporary hold and `custom_time`, and verify `object_checksums` with Cloud Storage's refusals. See [Storage v2 update and copy](../slices/grpc-v2-update-copy.md).
- Bucket and default object ACL entries for a team of the bucket's project carry `entity_alt`, and a soft delete policy with duration 0 has no `effective_time`.
- A legacy v1 bucket reports its project number.

### XML API and listings

- Custom metadata keys that differ only in case are served as one `x-goog-meta-` field joining their values in key order, where 0.25.0 refused the GET and HEAD.
- The bucket, default object and object ACL listings answer `If-None-Match: *` with 304 and a failing `If-Match` with 412; the notification and HMAC key listings ignore both. A successful restore answers without an `ETag` header.

### `gcs-mimic buckets new`

- The questions run in a terminal interface: bucket names several at once, public or private per bucket, then goals such as browser uploads and downloads with a CORS rule browsers can use, and the other settings behind More settings. Esc goes back one step, and before writing the buckets are shown in words with write, add, change, remove and cancel.
- A JSON document bound for a terminal is saved to a file the questions ask for, offering another file or printing when it cannot be created, as in the image's working directory. An existing `--output` is refused before the first question.
- `--browser-uploads` and `--browser-downloads` add what the goals of the same names add. See [container usage](../container-usage.md#initialize-bucket-settings) and [bucket initialization](../slices/bucket-initialization.md).

### Differential harness

- The reference grows from 124 to 147 cases; the [evidence page](../evidence/provider-differential-gap-probes.md) describes the recordings. Each case's normalizer hides every project number the run has seen.

## Compatibility and migration

A data directory from 0.8.0 through 0.25.0 is migrated to catalog schema 57 when 0.26.0 first opens it; afterwards only 0.26.0 or later opens it. The migration renames project teams stored with number 0 to the owning project's number and adds two nullable columns, and no data directory is reset.

A `gcs-mimic sync` command and the server it manages must still be the same release, so upgrade both together. The Go packages accept a binary of the same minor release, so upgrade the Go module to 0.26.0 together with the binary.

## Dependencies and project

- `bytes` moves to 1.12.2, which fixes sign extension in `try_get_int` and `try_get_int_le`, releases the shared reference when `Bytes` is truncated to zero length and keeps the buffer order in `Chain::chunks_vectored`. The build image pins the `rust:1.100.0-slim-trixie` index rebuilt to add linux/riscv64; its linux/amd64 and linux/arm64 manifests are unchanged, and the Rust toolchain stays 1.100.0. Development-only pins move to actions/setup-go v7.1.0, genproto 20261116 in the Go SDK suite, Testcontainers 4.17.0 in the .NET SDK suite and google-cloud-cpp v3.14.0 in the C++ scorecard probe, and the scorecard compares against floci-gcp 0.13.0. The package version and the Go module's `ModuleVersion` move to `0.26.0`, and the recipes pin `0.26.0`.
- The Go module, tagged `go/v0.25.0` with release downloads and `go 1.26.0`, is tagged `go/v0.26.0` after publication, once its `SHA256SUMS` records this Release's archives.
- The released-data fixture for 0.25.0 joins the upgrade test, so data directories from 0.8.0 through 0.25.0 are opened by the new build.
- The [feature ledger](../../../compatibility/features.json) records the new answers on 57 rows, none of which changes status, and the [gap ledger](../../../compatibility/gaps.json) resolves LOCAL-RETENTION-WINDOWS-TICK, SPEC-009, SPEC-010, SPEC-011, SPEC-JSON-ETAG-COLLECTIONS, SPEC-JSON-UNKNOWN-QUERY-OBJECTS, SPEC-METADATA-IF-MATCH, SPEC-OBJECT-HOLDS-CUSTOMTIME, SPEC-RESUMABLE-DECLARED-LENGTH-OVERRUN, SPEC-RESUMABLE-RUNNING-HASH, SPEC-RSM-DISCOVERY-PATH and SPEC-VERSION-DELETE-CONDITIONS.

## Known limitations

- The released-data fixture for 0.26.0 and the Go module's `SHA256SUMS` for 0.26.0 are added after publication, as for earlier releases. Until `go/v0.26.0` is tagged, a Go module revision between this release and that commit cannot download its binary; set `GCSM_BINARY` there.
- Unrecorded edges stay local choices that the ledger names: `If-None-Match`, date conditions and `If-Range` on metadata writes keep their 400, the XML POST policy form keeps refusing a bare `x-goog-meta-` field, Storage v2 bucket label masks still replace, and `kms_key` and `destination_kms_key` stay `UNIMPLEMENTED`. Managed folders are not implemented.
- A new bucket retention policy reports its `effectiveTime` at the request time; Cloud Storage reported about 60 seconds later in one observation without changing what it enforced.
- The limitations listed for [0.25.0](0.25.0.md#known-limitations) still apply, and these changes do not close the [1.0.0 gate](../release-policy.md#the-100-gate).

## Verification

The [release workflow](https://github.com/shiroemons/gcs-mimic/blob/v0.26.0/.github/workflows/binaries.yaml) creates this Release only after `validate`, including the dependency freshness check, Foundation and all eight native build/test jobs succeed at the tag's SHA. The [container workflow](https://github.com/shiroemons/gcs-mimic/blob/v0.26.0/.github/workflows/ghcr.yaml) then builds both Linux architectures natively, verifies their SBOM and provenance, publishes the multi-architecture tag and checks anonymous pulls, and the Docker Hub workflow mirrors that digest.

The tag was first pushed on the commit before the `bytes` and Rust index update. Its `validate` job stopped because both had been published after that commit's dry run, and it published nothing; the tag was recreated on this commit once its own dry run had passed.

Before tagging, `just pre-push` (the native checks with 3950 Rust tests, every pinned SDK suite and both container architectures), `scripts/check-cross.sh` and the release-scoped dependency freshness check passed on the release source. The full freshness check reported four development-only updates that this release does not adopt: google.golang.org/api v0.316.0, `bytes` 1.12.2 in the Rust SDK suite and scorecard, Java `google-cloud-storage` 2.79.0 and PHP `google/cloud-storage` 2.7.0. The Foundation checks replay all 147 differential cases without a difference.
