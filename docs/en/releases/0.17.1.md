# gcs-mimic 0.17.1

0.17.1 fixes one defect: a container with a small memory limit could be OOM-killed while receiving a large object. Nothing else changes, and no setting or data needs attention when upgrading from 0.17.0.

It publishes `ghcr.io/shiroemons/gcs-mimic:0.17.1` for `linux/amd64` and `linux/arm64`, mirrors the same digest to Docker Hub as `shiroemons/gcs-mimic:0.17.1`, and publishes native archives for all eight macOS, Windows and Linux targets. The [feature matrix](../feature-matrix.md) lists the exact supported subsets. Rows marked `PARTIAL` keep their listed missing cases.

## Changes

### Large uploads under a memory limit

- A 1 GiB upload to a container limited to 128 MiB could end with the kernel killing the server, although the process itself held about 16 MiB. The body was written through the page cache and synced once at its end, so a busy disk let unwritten pages fill the container's limit. It happened with the data directory on the container's own filesystem layer, which is what `docker run` without a volume uses.
- On Linux a body is now synced after every 8 MiB written. This covers single-request, multipart and resumable uploads, XML multipart uploads, and the copies made by rewrite and compose.
- In the same session 0.17.0 lost 17 of 120 such transfers and this release none of 140. Upload time did not get worse. The [measurements](../evidence/upload-dirty-page-limit.md) list the conditions and the kernel's report.

## Compatibility and migration

0.17.1 keeps catalog schema 52. A data directory that 0.17.0 used opens without a migration. No command, option, environment variable, default or API response changes.

Releases before 0.17.1 have the same defect. If one must stay in use, give its container 256 MiB or more, or put its data directory on a volume.

## Known limitations

- The fix bounds the unwritten bytes of each body, not the container's memory. Each concurrent upload can hold 8 MiB unwritten, and written pages stay cached until the kernel reclaims them.
- It was measured on one Docker Desktop host with the data directory on overlayfs. Other filesystems and Linux hosts were not measured.
- macOS and Windows keep the single final sync. They do not charge the page cache to a process limit in this way.
- The limitations listed for [0.17.0](0.17.0.md#known-limitations) still apply, and this change does not close the [1.0.0 gate](../release-policy.md#the-100-gate).
