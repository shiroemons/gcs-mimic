# アップロードとコピーの再試行

正本は[英語の契約](../en/slices/sdk-upload-replay.md)です。
対象のJSON-OBJECTS-003・007、BEHAVIOR-OBJECT-008・009はPARTIALのままです。

アップロードとコピーの再試行では、公開結果を10分間、全体で最新の4096件まで保持します。
上限に達したら新しい書き込みを失敗させず、最も古い記録を捨てます。

**保証の範囲は次のとおりです。** 同じ結果を返すのは、記録が残っている再試行だけです。
10分を過ぎた再試行と、記録が捨てられた後の再試行は、新しい書き込みとして扱います。
つまり同じ内容をもう一度公開します。短時間に4096件を超える単発アップロードやコピーがあると、10分より前に記録が捨てられることがあります。
これが起きるのは冪等トークン付きの単発アップロードとcopyだけです。resumableはこの記録を作らず、セッションのオフセットで再試行を判定します。
重複を許せない再試行には、`ifGenerationMatch`などの条件を付けるか、書き込みの結果を読み直してください。

要求の識別には、長さと省略値のタグを含む、版を固定したバイナリ形式を使います。
v2形式では既定のマップマージのdigestを維持し、マップ全体の置換だけに明示タグを加えます。
マージと置換が異なる要求を再利用することはありません。全メタデータ項目の差異をテストし、
Debugの診断表示を要求識別の互換形式には使いません。
同じ要求は元の公開結果を返し、内容が変わった要求は400として拒否します。
コピーの転送中にソースバケットが削除・再作成された場合は、公開時にも412を返します。

旧形式で保存された要求は、アップグレード後、元の保持期限まで再試行が400になることがあります。
この拒否では二重に公開しません。新しい要求を送る前に、既に公開されたオブジェクトを確認してください。
